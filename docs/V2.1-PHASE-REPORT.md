### 本次修复的两个真实缺陷

1. **受管装配缺演化围栏**（严重）：`run-managed.mjs` 创建演化运行时未传策略，
   落到缺省 `FULL_CORE_POLICY`——冷却 0、变化数无上限、**不禁止触碰玩家**。
   真模型实测中启动回放 7 个 High 事件连发 7 次无节流 AI 调用。
   已接入 `NPC_EVOLUTION_POLICY`（动作白名单 / 禁触玩家 / 3 变化 3 实体 / auto·api 30s 冷却），
   实测第二次 auto 触发被 429 `evolution_cooldown` 正确拦截，admin 手动不受限。
2. **日程命令误移玩家**（本次新代码，被地毯式测试抓出）：引擎 `move_entity` 规则中
   `targetId === actorId` 会被解释为玩家移动；日程命令原携带 `actorId: id`，
   导致时间推进把玩家传送到 NPC 的日程地点。已修正（日程命令不带 actorId），
   并在单测中固化该约束。

## 3. 架构影响

- 平台面新增 `npc/` 模块：机制通用（任意游戏可挂日程表），日程表属游戏数据归宿主——符合 §十八 Core 纪律。
- 受管装配围栏与测试用例对齐：测试里的保证第一次在生产装配线上生效。
- 宿主新增确定性日程通道：`World Time + Schedule + Rules` 负责确定性行为，AI 只管异常与临时行为（§九 分工落地）。
- 不变式保持：AI → Proposal → Whitelist → Rules → Mutation → Event 全链无旁路。

## 7. 已知问题

1. `admin-http` 登录节流测试与 gateway 3 例在机器高负载/并发跑时偶发失败，复跑即绿——建议引入假时钟消除真实等待依赖。
2. 参考宿主「买酒」不校验老周是否在场（宿主确定性经济的已知简化）。
3. `traceEvent` 反向追溯线性扫描最近 200 条 run——事件量大后的性能留待 Phase 12 压测。
4. 时间类 High 事件在宿主启动回放时会逐事件触发演化 tick（现被 30s 冷却兜底）；
   更优做法是「窗口内 High 事件合并为一次 tick」。
5. `WorldClock.tillMorning()`（睡到天亮）尚未暴露为 HTTP/命令。
6. **tianqiong2 GUI 游戏端是进程内接入**（引擎库同进程、同总线、同状态，有集成测试钉死），
   但未消费 8787/8790 的 HTTP/WS 闭环；V2.1 的网络闭环以参考宿主验证。
   游戏端切换为引擎 HTTP 客户端（消除双世界状态）是下一阶段首要工作。

## 9. 是否存在绕过 Rules

**无**。全部世界变化（玩家意图、AI 提案、日程对齐、宿主经济）都以 Command 进引擎 Rules 链；
唯一例外是宿主视图层（`gameView` 地名翻译）为纯读投影。日程对齐曾走
`move_entity` 旁路风险评估：不适用——它本身就是命令链。

## 10. 是否存在 AI 直接修改 State

**无**。演化运行时对世界的全部操作就是向 EngineClient 发 Command（与游戏方同权、零特权）；
AI 侧影响力被压缩为 Proposal，经白名单翻译 + Rules 终审才可能成为 Mutation。
受管装配本次补上 `NPC_EVOLUTION_POLICY` 后，AI 连「提议触碰玩家」都会在策略层被拒。
