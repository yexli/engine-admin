# 游戏接入平台规划（GAME-PLATFORM-PLAN）

> 制定日期：2026-10-01 · 状态：**规划稿（待确认后分期实施）**
> 目标：让 world-engine 从"单游戏内嵌库"升级为**多游戏可接入的托管平台**——
> 任何游戏方/开发方按契约接入，世界在剥离引擎上运行，管理后台全量可见。
> 天穹（tianqiong2）为第一个参考接入方。
> 前置事实（已验证）：天穹源码已构建在引擎上（1716 测试对 1.0.3 全绿）；
> 天穹世界书数据已可在引擎上建模（run-demo-engine 的 tianqiong-main，后台可见）。

---

## 1. 目标形态

```
┌──────────┐   ┌──────────┐        ┌─────────────────────────┐
│ 游戏方 A  │   │ 游戏方 B  │  …/…  │  引擎托管服务（registry）  │
│ 客户端/SDK │──▶│ 客户端/SDK │──HTTP──▶  多世界 · 多游戏 · 生命周期  │
└──────────┘   └──────────┘        └───────────┬─────────────┘
                                    ┌──────────┴─────────────┐
                                    │ 管理后台（全量可观测/管理）│
                                    └────────────────────────┘
```

两类接入模式（游戏方按产品形态自选，可并存）：

| 模式 | 说明 | 后台可见性 | 离线能力 |
|---|---|---|---|
| **托管式**（Hosted） | 世界运行在托管服务的进程里，游戏客户端经 HTTP/WS 驱动 | 全量（世界/状态/事件/生命周期/计量） | 无（服务在则世界在） |
| **嵌入式**（Embedded） | 游戏进程内嵌引擎库（天穹现状），另起上报桥把事实/状态推给平台 | 仅上报的事实与状态快照（事件流/记忆） | 完整离线 |

## 2. 现有资产 → 目标组件的映射

| 目标组件 | 现状 | 缺口 |
|---|---|---|
| 多世界托管 | ✅ 引擎 `createWorldRegistry` + `startWorldServer`（w-main/w-test/tianqiong-main 三世界并存已实测） | 世界**归属**（属于哪个游戏方）与**隔离** |
| 世界创建 API | ✅ `POST /v1/worlds`（registry 模式 + World Definition） | 鉴权（已知问题 #4）+ 归属字段 |
| 生命周期 | ✅ 1.0.3 暂停/恢复/关闭 | 无 |
| 观测面 | ✅ 状态/实体/关系/事件/调度/命令历史（M1.3/M1.4） | 事件**实时推送**（现在轮询） |
| 计量面 | ✅ 用量数据面（M2.2） | 按游戏方分组的计量维度 |
| 管理后台 | ✅ 世界/事件/关系/生命周期全可见（M4） | 「游戏方」管理视图（按接入方聚合） |
| 角色记忆 | ✅ world-memory（每世界一 store；嵌入可配置） | 服务端 SavePort（演示为内存/文件） |
| AI 网关 | ✅ world-gateway + 平台计量/路由/思考强度 | 游戏方直接使用的鉴权与配额 |
| **游戏适配器契约** | ❌ 缺失——这是唯一的新大陆 | 见 §3 |

## 3. 核心：游戏适配器契约（可复用的关键）

方案原文的定义："Adapter 解决『这个游戏如何接入引擎』（数据转换 / 实体映射）"。
产品化为一层**薄契约**（建议作为引擎子路径导出，如 `world-engine/adapter`，零依赖同纪律）：

```ts
export interface GameAdapter {
  /** 游戏名/ID（归属与计量维度） */
  gameId: string;
  /** 世界书/设定 → 引擎 World Definition（地点/NPC/关系/元数据） */
  definition(): WorldDefinition;
  /** 游戏命令词表 → 引擎命令（双向：引擎事实 → 游戏可读文本也在此声明） */
  commands: {
    toEngine(cmd: GameCommand): EngineCommand | null;
    describe(fact: WorldEvent): string;   /* 事实 → 游戏可读文本 */
  };
  /** 感知边界声明：哪些 owner 能"看见"哪些事实（缺省 = actor + target） */
  witnessesOf?(fact: WorldFact): string[];
}
```

- 契约只做**映射**，不承载规则——规则仍在引擎（规则是引擎最重要的扩展点，不变）；
- 天穹 → 第一个参考实现：`worldBook.json + people.json → definition()` 已验证可写；
  命令映射（travel→move / shopBuy→economy 命令族…）是 G1 的主要编写工作量；
- SDK 形态：引擎子路径导出 + 一份接入指南，第三方不需要读引擎源码。

## 4. 分期路线（每期独立可验收）

### G1 · 接入规范 + 参考实现（天穹 HTTP 宿主）✅ 已交付（2026-10）
- ✅ 契约 `world-engine/src/adapter.ts`（v1.0.4）：`GameAdapter`/`GameWorldSeed`
  类型 + `definitionFromSeed` 纯映射 + `hostGameWorld` 装配辅助；适配器测试 5 个；
- ✅ tianqiong2 `scripts/http-host.mjs`（纯 JS，`node scripts/http-host.mjs` 即起）：
  读世界书 geo/people → GameAdapter → `hostGameWorld` → `startWorldServer`（8798）；
- ✅ 实测（curl 验证）：tianqiong-main 世界 63 地点 / 15 NPC / 10 关系 / 40 事实
  事件全量落库；暂停→写命令 409→恢复闸门正常；
- ✅ 后台可见性：admin-web 的 `/world-api` 代理目标由 `VITE_WORLD_API_URL`
  控制，指向 `http://127.0.0.1:8798` 即在控制台看到 tianqiong-main
  （缺省 8787 仍是演示世界 w-main/w-test，两者可切换）；
- 天穹桌面版**不变**（嵌入式现状保留，离线能力不受影响）；
- DoD 达成：后台可见 tianqiong 世界；引擎测试 95 全绿只增不减。

### G2 · 多游戏托管（平台侧）✅ 已交付（2026-10）
- ✅ **世界归属**：`WorldInfo.ownerGame`（引擎 1.1.0，metadata 通道随存档持久化）；
  `GET /v1/worlds?game=` 过滤；适配器种子 `GameWorldSeed.ownerGame`；
- ✅ **世界 API 鉴权**（已知问题 #4 关闭）：引擎 HTTP 面可选中间件
  `auth: { keys: Record<string, WorldAuthKey> }`（缺省关，云部署开）——
  401 全路由闸门 / 403 写入类需 `worlds:write` / 游戏方钥匙只见
  `ownerGame` 匹配的世界（越权 404 不泄露存在性）/ 建世界强制归属盖章；
  钥匙事实在接入方（平台 KeyStore 语义），引擎零依赖；
- ✅ **游戏方钥匙**：平台 `ApiKeyRecord.gameId`（0.6.0），管理台创建 Key 可
  填 gameId，清单回显归属；
- ✅ **管理台「游戏方」视图**（admin-web /gateway/games）：按方聚合
  世界（数量/健康/实体/最近活动）与钥匙；用量按方报表归 G3 计量增强；
- ✅ DoD 实测：`scripts/run-g2-demo.mjs` 16/16 通过——两个模拟游戏方
  各自建世界、互相不可见（404 不泄露）、冒名归属被改判、后台按方聚合可见。

### G3 · 产品化（实时 + 持久 + 配额）✅ 核心已交付（2026-10）
- ✅ **WebSocket 事件推送**（引擎 1.2.0，零依赖 RFC6455 最小实现）：
  `/v1/worlds/{id}/events/stream` + `/v1/stream`（后建世界自动补挂）；
  `?replay=N` 断线衔接；鉴权同 HTTP 面（游戏方隔离一致）；admin-web
  事件页「实时」按钮直连（vite 代理 ws:true，断线回落轮询）；
- ✅ **服务端 SavePort（文件）**：`FileSavePort`——写后置 + 原子写 +
  损坏档备份不静默覆盖；载入编排 = 宿主读档经 `container.core.S` 注入
  （正典模式）；`hostGameWorld` 第三参支持 `savePort`（适配器 × 持久化组合）；
- ➡️ PostgreSQL 介质：属部署层适配（实现同一 SavePort 接口），不进引擎
  （零依赖纪律）；随云端部署（平台 Phase 8 对齐）落地；
- ✅ **计量增强**：`UsageEntry.gameId` 维度（平台 0.7.0）——usage 查询
  `game_id` 过滤（`__platform__`=平台钥匙）+ `group_by=game`；钥匙带
  gameId 的调用自动盖章归属；
- ⬜ 配额/限流：维持「可选，产品决策」，暂不做；
- ✅ DoD：`docs/SDK-GUIDE.md` 从零接入指南（安装 → 30 行宿主 → 持久化 /
  实时流 / 隔离鉴权 / 规则挂载），`scripts/run-g3-demo.mjs` 实测 6/6——
  第三方不改引擎代码接入最小世界，后台全量可见。

## 5. 明确不做（维持边界）

- 游戏逻辑进引擎：规则仍由接入方经 `registerRule` 挂载，引擎不含玩法语义（§不变量）；
- 天穹桌面版的产品方向改造（单机离线形态保留，服务化由天穹方自行决策）；
- SillyTavern 兼容（原明确不做项，维持）；
- 多租户计费/账单（平台 Phase 2 范畴）。

## 6. 风险

| 风险 | 缓解 |
|---|---|
| 命令翻译层覆盖度（游戏词表≠引擎词表） | 契约允许 game command 原样透传给宿主的**游戏侧执行器**——引擎只承接通用子集（移动/时间/关系/实体），玩法命令由游戏在自己进程执行后把**结果事实**喂回（ingestFact/emitEvent 本就是公开 API） |
| 嵌入式游戏的上报可靠性 | 上报桥失败本地缓存重试；后台标注"快照延迟" |
| 鉴权引入后的兼容 | 引擎 HTTP 鉴权做成可选中间件（缺省关，云部署开），不破坏既有本地用法 |
| 无 git 的交付形态 | 契约包随引擎版本发布，版本号严格递增 |

## 7. 托管平台路线（P 系列 · 通用 AI 世界运行托管）

> 定位升级（2026-10）：从「游戏接入平台」升格为「**AI 世界运行托管平台**」——
> 任何方（游戏 / 小说 / 任何需要世界推演的场景）都能把世界交给平台托管运行，
> 平台负责运行、可观测、持久化、计量与隔离；引擎逻辑的持续优化由平台方承担。

### 现状 → 目标的差距（诚实清单）

| # | 差距 | 现状 |
|---|---|---|
| 1 | 接入是**工程动作**（跑 http-host 脚本）不是**自助动作**（网页操作） | G1 的宿主脚本要进接入方仓库 |
| 2 | 引擎宿主进程由接入方自己起 | 没有「平台统一托管运行服务」 |
| 3 | 非结构化数据（小说文本）→ GameWorldSeed 无 AI 抽取通道 | 世界书 JSON 要自己整理 |
| 4 | 配额/限流未做（G3 标注可选） | 公开运营必需 |
| 5 | 持久化介质在接入方进程手里 | 托管形态须平台管存储/快照/恢复 |
| 6 | 无客户端 SDK（远程直连） | 消费端（游戏客户端/编辑器）要手写 HTTP/WS |
| 7 | 部署为本地 compose 草稿 | 公网硬化（TLS/PG/备份）未做 |

### 安全边界（托管形态的第一设计决定）

**平台代跑的是数据种子，不是接入方代码。** 自助托管只接受 GameWorldSeed
形状的**数据**（世界书 JSON / AI 抽取结果）；玩法规则来自平台内置模板库
（RPG 规则集 / 叙事推演规则集，按世界模板选用），**不接受接入方提交任意
规则代码**——否则平台就是任意代码执行服务。接入方要自定义玩法语义的，
仍走 G1 的嵌入式/自托管形态（SDK 指南），两条路径并存。

### P1 · 托管运行服务（库 → 服务，形态转折点）
- 平台内置 World Hosting：平台自有的引擎进程（registry 模式常驻），
  世界创建/暂停/恢复/关闭走平台管理 API；平台为每个世界挂 FileSavePort
  （数据目录按 `gameId/worldId` 分桶）+ 定期快照；
- 模板规则库 v1：内置 RPG 规则集（移动/交易/关系演化）+ 叙事推演规则集
  （时间推进 → AI 生成事件，经 world-agent 管线，M2.3 桥接已有）；
- console 补「创建世界」向导（选游戏方 / 选模板 / 贴种子）；
- DoD：接入方不跑任何脚本，console 里建世界即得一个跑在平台进程里的世界。

### P2 · 自助接入中心（世界书上 → 世界起）
- console 新页「接入中心」：建游戏方 → 上传世界书 JSON（或文本）→
  校验预览（地点/NPC/关系统计 + 非法项报告）→ 一键 launch → 发钥匙
  （明文一次性展示）；
- **AI 世界书抽取（小说模式）**：粘贴/上传文本 → world-agent 抽取
  GameWorldSeed（地点/人物/关系/身份）→ 人工确认修订 → launch；
  这是「做小说的」接入路径，也是平台差异化能力；
- DoD：一个不了解本仓库的人，10 分钟内从文本/JSON 到一个运行中的世界。

### P3 · 配额与限流（公开运营前置）
- Key 维度配额：日请求数 / 日 Token 上限（数据面已具备 gameId 维度），
  超限 429 + 明确错误码；console 可编辑配额与用量逼近曲线；
- DoD：给测试钥匙设 100 次/日 → 第 101 次 429，后台可见逼近曲线。

### P4 · 客户端 SDK（`world-engine/client`）
- 把 HTTP/WS 包装成与进程内同形的接口（executeCommand / advanceTime /
  getEvents / 事件订阅），消费端（游戏客户端、编辑器、天穹远程模式）换一个
  import 即切远程托管；
- DoD：天穹以环境开关从嵌入式切到平台托管世界（只读面先行）。

### P5 · 云端硬化与发布
- compose 全栈 + nginx TLS + 数据卷 + 备份计划；平台存储 PG 迁移（Phase 8
  既定线）；引擎 PG SavePort 部署适配；SDK 指南文档站化发布；
- DoD：一台干净 VPS 一条命令起全栈，公网可走完 P2 全流程。

### 顺序与依赖
P1 → P2 → P3 为主线（形态 → 门面 → 运营安全）；P4 可与 P3 并行（纯引擎面）；
P5 收尾。规模天花板到达前（单机文件存储 / 单进程世界数），P5 的 PG 与进程池
隔离按量启动，不提前建设。
