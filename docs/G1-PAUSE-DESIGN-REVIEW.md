# G1 设计评审记录：世界暂停 / 恢复 / 关闭（软暂停先行）

> 评审日期：2026-09-30 · 状态：**已评审通过并按此实施**
> 依据：ADMIN-CONSOLE-ROADMAP M4.2（「唯一可能触碰 Core 的工作项：先出设计评审记录，
> 再动引擎」）· GAP G1 · 决策点 4（软暂停是否够用由引擎侧评审定，不预设结论）
> 关联：已知问题 #4（引擎公共面无鉴权，不在本评审范围）

## 1. 背景与需求

管理后台需要对世界执行生命周期操作，并把状态反映到列表：

- **暂停**：世界时钟与命令推进停止，读操作（状态/事实/实体查询）不受影响；
- **恢复**：解除暂停；
- **关闭**：世界从注册表移除，不再可访问；
- 列表/Monitor 显示 running / paused 状态；关闭后的世界从清单消失。

## 2. 备选方案

| 方案 | 说明 | 评估 |
|---|---|---|
| A. Runtime 级暂停（Core 改动） | WorldRuntime 增加 paused 状态，execute/advance 入口短路；暂停语义进 Core，随 SavePort 持久化 | 语义最完整，但**触碰 Core**（V1.0 公开 API 冻结纪律）；暂停状态进存档还牵动 SavePort 契约与存档兼容性；收益：暂停状态跨进程重启 |
| B. HTTP 适配层软暂停（零 Core） | 引擎 HTTP 层维护 per-world 暂停集合；暂停时 `POST .../commands` 与 `POST .../time` 返回 409 `world_paused`；读路由照常；`DELETE /v1/worlds/{id}` 走 `WorldRegistry.close()`（V0.9 已有） | 零 Core；管理后台的场景（运营性暂停）够用；暂停状态进程内 |
| C. 平台侧拦截（零引擎改动） | 平台代理层拒绝对特定世界的写透传 | 引擎直连流量（绕过平台）不受控——状态权威分裂，否决 |

## 3. 决策

**采纳 B（HTTP 适配层软暂停）**，理由：

1. **公开 API 冻结纪律**：全部为增量（3 个新路由 + WorldInfo 可选 `status` 字段），
   既有形状零改动、零行为变化——与 1.0.1 同款纪律；
2. **决策点 4 的答案**：软暂停已够管理后台使用，不需要 Runtime 级 pause。
   Runtime 的职责边界是「命令如何被校验与执行」；「对外服务是否受理命令」是
   **服务面（HTTP 适配层）的运营决策**，如同端口开关，不属于世界语义；
3. `WorldRegistry.close()` 在 V0.9（DR-003）即已存在，关闭是**既有能力的 HTTP 暴露**，
   非新语义；
4. 暂停状态**进程内**（不进存档）：演示与本地运营宿主用 `InMemoryWorldStorage`，
   世界本身就不跨重启——为进程内存活期不超过世界本身的标记做持久化是伪需求。
   真实的持久化世界（SavePort/Phase 8 PostgreSQL）若需要跨重启暂停，
   届时把标记写进 `state.metadata`（M1.5 同款通道）即可，契约已留好
   （`WorldInfo.status` 的读取方不关心标记存哪里）。

### 3.1 语义明细（本评审的裁定，实现照此执行）

- `POST /v1/worlds/{id}/pause` → 暂停；重复暂停 409 `world already paused`；
- `POST /v1/worlds/{id}/resume` → 恢复；未暂停时 409 `world not paused`；
- `DELETE /v1/worlds/{id}` → 注册表摘除（`registry.close()`）；单世界模式不支持
  （409 `close requires registry mode`——单世界就是进程本体）；摘除同时清暂停标记；
  关闭后的世界一切访问 404（与「从未存在」同响应，不区分——诚实且无状态可泄）；
- 暂停中：`POST .../commands`、`POST .../time` → 409 `world_paused`（body 含提示）；
  **全部 GET 照常**（含 scheduler 的延迟事件——暂停期间不清空、到期不分发由
  bus 现有语义决定，不在本评审扩展）；
- `WorldInfo` 增加可选 `status: 'running' | 'paused'`（关闭态不存在于任何响应）；
- 暂停/恢复本身**不写** `updatedAt`（不是世界推进，是运营动作）。

## 4. 影响面与回滚

- 影响面：`world-engine/src/http/protocol.ts`（路由 + 门 + info 增字段）、
  `WorldInfo` 类型（可选字段）、新增测试；Core（runtime/rules/state）**零改动**；
- 回滚：移除 3 个路由与 status 字段即回到 1.0.2 行为；暂停集合是协议内部状态，
  无持久化残留。

## 5. 验收（实现后逐条核对）

1. 引擎测试：暂停 → 命令/推进 409、读 200、重复暂停 409；恢复后命令照常；
   未暂停恢复 409；关闭后清单消失、访问 404；单世界模式关闭 409；status 字段入清单；
2. 引擎 86 基线全绿（增量 only）；
3. 管理后台浏览器实测：列表状态标签、暂停/恢复/关闭实操作反映到列表
   （DoD：世界可暂停/恢复/关闭并反映到列表状态）。
