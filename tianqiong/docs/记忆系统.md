# 记忆系统（Memory Engine）落地说明

> 依据：《AI 世界模拟引擎——Memory Engine 记忆系统设计方案》
> 记录**已经落地**的部分与真实契约；未落地的在 §7 明确列出。
> 与《插件化世界模拟架构.md》是姊妹文档：那份讲世界怎么运转，这份讲角色认知怎么形成。

## 0. 一句话

**World Truth ≠ Character Memory ≠ Belief ≠ Rumor。**
世界史（`worldEventLog`）记客观事实；感知表（`WorldState.knowledge`）记「谁看见了哪个事件」；
记忆表（`WorldState.memories`）记「这个角色记得什么、记得多清楚、从哪知道的」。

---

## 1. 三层认知数据的分工

| 层 | 载体 | 语义 | 谁在用 |
|---|---|---|---|
| 世界真相 | `WorldState` + `worldEventLog` | 客观发生了什么 | 推演、审计、因果链回溯 |
| 感知表 | `WorldState.knowledge` | 谁看见了哪个事件（事件级） | 调查取证、目击者反应 |
| 记忆表 | `WorldState.memories` | 角色记得什么（角色级，可衰减） | AI 上下文召回、传话 |

三者**都随存档持久化**，旧档由 `hydrate` 补空表（「没人知道任何事」是安全默认）。

## 3. 关键契约

**§9 强度**：`importance × confidence × exp(-decayRate × 经过天数)`，时间用**世界日**（与 WorldClock 同源，不引入第二套时间）。

**§9 衰减分档**：重要度 ≥0.9 → 衰减率 0（人生重大事件永不遗忘）；0.6/0.3 分档递减。

**§10 强化**：被想起的记忆更牢固——但**只延长保留期，绝不改置信度**。
「被想起 ≠ 被证实」：把召回记到 confidence 上，会让一条推测在几次顺手取用后变成铁证（§37 击穿）。
衰减锚点因此取 `lastRecalledAt`（反复回忆的记忆自然留得更久）。上下文构建是**纯读**，不写状态；
显式强化走 `memoryEngine.recall`。

**§22 传播**：传播不是复制而是重新计算——置信度按手数衰减、来源改写为「听说」、重要度随之走低，低于阈值自然断链。

**§36 权限**：检索只回本人记忆；`secret` / `restricted` 不外传（**`private` 可以转述**——私家经历本就该能讲出来，堵死它会让谣言系统整个瘫痪）。
提案层另有硬约束：`type:'secret'` 不得同时声明 `visibility:'public'`；`direct_observation` 必须带 `sourceEventId`。

**§11 向量与检索的时序契约**：向量是**派生数据**（由内容决定、随时可重算），
1024 维浮点 × 每条记忆入档会让存档膨胀几个数量级，因此只活在内存缓存里。
检索侧保持**同步**、只读缓存；向量化由 `warmQuery` / `warmMemories` 在推演开始前异步完成
（`WorldReasoner.reasonAbout` 已接）。缓存未命中时语义项权重整体剔除、其余分量重新归一化——
没预热只会退化成关键词召回，不会算出错误分数。缓存按内容指纹失效。

**§22 同源**：传播**同时**写记忆表与感知表——调查系统读感知、AI 推演读记忆，
只写一边会让同一个 NPC 在两处对不上（被调查时「不知道」，被问话时却「记得」）。

**§26 压缩与遗忘的顺序契约**：日边界**先归并、后遗忘**。反过来的话，衰减会先把琐碎旧记忆标成 forgotten，而压缩只处理 active 条目——它们永远压不到，长期只会堆积。压缩产物会**提升为 `knowledge` 型并重算衰减率**，否则刚归并的摘要会在下一轮衰减里立刻沉底。

**传话用确定性节律而非随机**：`gossipTick` 每 3 天一轮。若在这里消耗主随机序列，会让所有依赖种子复现的既有测试集体位移——世界自己会传话，但不该扰动骰子。

## 4. 与推演的连接（§39）

```
World Event → Event Bus → 感知层判定目击者 → Memory Engine 生成角色记忆
                                                    ↓
玩家/NPC 交互 → Memory Retrieval → Context Builder（Token 预算）→ World Reasoner
                                                    ↓
                                     Consequence Plan → Validator → Executor → 新事件
```

`ai/ContextBuilder.ts` 会为事件相关角色装配 `memories`（已过权限过滤与预算），
与「认知边界」（`knows`）并列——推演器因此能区分「他记得什么」与「他此刻知道什么」。

**再加一层 `beliefs`（§23）**：由记忆聚合出的信念（置信度 ≥ 0.4、按置信度取前 5 条）也进上下文，
Consequence Planner 里单独成段「各角色相信的事（行动动机来自这里，而不是世界真相）」。
少了这一层，「某人坚信玩家有罪」与「玩家确实有罪」在模型眼里没有区别，NPC 就只能对世界真相做反应。

## 5. 事件 → 记忆

`recordFromEvent` 复用**感知表**拿目击者，不重新判定视线：感知只做一次，避免两套口径。
L0 内部账目（掉血、扣蓝）不会成为任何人的记忆。

重要度与情绪按事件类型映射（死亡 → 恐惧、罪案 → 愤怒、委托完成 → 喜悦），映射表配置化。

## 5.5 认知层单源（老表退役）

审计整改：`NpcDynamic.mem`（卡 D2 的「文本 + 粗档 imp」）与记忆表曾长期并存——
老表被 8 个系统直接写入、**永不衰减、无可见性规则、无校验闸**，
而衰减 / 遗忘 / 私密边界 / `MemoryValidator` 全都只在新表生效。
同一个 NPC 对同一件事会两处各存一份，措辞还不一样，而推演器同时看到两份
（`ContextBuilder` 的 `mem` 与 `memories`）——这正是「两套真相来源」。

现在的单向规则（**半迁移 = 0**）：

```
写入 —— 只走 MemoryEngine；systems 侧的 addMem 是它的适配器（老表不再被写）
读取 —— 只走 memory 的 memOf 投影；UI / 对话 / 规则模拟不再直接摸 npcs[id].mem
历史 —— migrateLegacyMemories 在载入存档后一次性搬入新表，并清空老表（幂等）
```

设计取舍与理由：

- `imp`（1–3 粗档）映射到重要度 0.3 / 0.5 / 0.7，**刻意不映到 0.9**——
  那一档是「人生大事、衰减率为 0」，日常的「收了你的礼物」「传闻·…」不该占它。
- `tier: 'secret'` 迁移时保住为 `visibility: 'secret'`——它是唯一会被传播侧拒绝的档，
  降级成 private 就等于把私密记忆放进传话池。
- 感知口径（与 `Perception` 一致）：**当事人必然知情**（被偷的、被改变态度的写在事件自带的
  `witnesses` 里，无条件计入），其余在场者才按显眼度抽样。好感变化的显眼度是 0 ——
  旁人看不见你心里的秤，但**被改变态度的那位自己**会被记进感知表与记忆。
- `memOf` 是**展示与对话专用**的投影：只回最近 12 条，且排除「引擎按世界事件自动写下的亲历观测」——
  那一族属于检索与推演层，而且与目击者反应写下的那条人际记忆是同一件事的两份措辞
  （引擎写「你犯下了罪行（theft）」，紧跟着写「恶感·目击罪行」）。
  需要全量记忆用 `memoriesOf`，需要按相关度召回用 `memoryEngine.retrieve`。
- 老表字段仍留在存档结构里（旧档可读），但**没有任何写入者**，
  迁移后为 `[]`；`compressMem` 分级压缩随之退役，容量只剩记忆表那一套规则。

## 7. 已知边界（当前实现范围）

### 已落地

- **Phase 2/3**：`ai/embeddingCompat` 实现 OpenAI 兼容的 `/embeddings`（维度首调探测），
  在「系统 → AI 网关 → 向量模型」页签配置；`memory/vector/VectorStore` 承载向量本身
  （§13 契约 + 内存实现 + 容量 LRU + 余弦检索），**事实与向量分表存放**（§29）。
- **向量可持久化**：`SavePort` 增加可选的 `loadVectors/saveVectors` 通道，
  浏览器端走独立键、桌面端另开一张 `vector_index` 表。
  **独立键不等于独立配额**——localStorage 的配额按**源**算，它与主存档共享同一份空间。
  导出因此按**字节预算**（900KB）而不是条数截断：同样 200 条在 1024 维下约 **3.9MB**
  （每个浮点在 JSON 里是完整十进制文本，约 20KB/条），是我最初估算的 5 倍，
  足以顶掉常见 5MB 配额的大半；存盘前还会把浮点降到 4 位小数。
  介质不实现该通道时静默退化为纯内存——只是重启后重算，不会出错。
- **语义打分**：由**缓存命中**决定是否计入权重，不再依赖硬编码开关
  （计入却算不出分量 = 等比稀释所有分数）。
- **Phase 6 势力通道**：NPC→势力上行 / 势力→成员下行；势力本身就是一个记忆主体，
  复用同构的 memories 表，容量与衰减机制不必重写。
- **Phase 7 核心（§24/§25）**：同命题记忆聚合成信念，原始记忆**永不因观点改变而被覆盖**；
  信念随日边界重算（放在衰减之后，只基于「此刻还认得的记忆」）。
- **§23 信念 → 行动的接口就位**：`Belief` 带结构化主谓宾（`subject/predicate/object`）
  与 `actedAt`/`actionKind`；`beliefActionsFor` 按 `data/world/memory.json` 的
  `beliefActions.rules` 找「哪条信念该驱动哪个行动」，`markBeliefActed` 写回「已驱动」以支撑 `once`。
  匹配逻辑抽成纯函数 `matchBeliefRules`，因此**内容表为空时机制本身仍可被合成规则验收**。
  **规则表当前是空的**——空表返回空数组，不会悄悄驱动任何东西。
- 记忆容量每角色 80 条（势力同），超出按当前强度淘汰；传播与压缩的写入都走 `putMemory`。

### 尚未落地

- **信念的可重建性已修**：命题（`主体|事件类型|客体`）在**写入记忆时定格**到 `Memory.proposition`，
  不再依赖不入档的事件日志。此前只看事件日志，加上 `formBeliefs` 无条件整体替换，
  导致**每次重启后的第一个日边界都会把所有信念清空**——比「滚出缓冲」严重一个数量级。
  现在：命题随记忆走、传播时继承、`propositionOf` 优先读字段（回退分支只服务老档），
  并在重建时保留「本次判不出命题」的旧信念作兜底。
- **向量行记录模型与维度**：`VectorItem`/`PortVectorRow` 带 `model`/`dim`，
  换 embedding 模型后旧向量在恢复时被丢弃——否则余弦会在两套向量空间之间
  算出一个「看起来合理」的分数。
- **§25 的矛盾判定只留了位**：`Belief.contradicting` 恒空——判定两条记忆"互相反驳"需要谓词级语义，
  当前只做到「同命题聚合」，冲突仍靠传播时的「亲历优先于传闻」近似。
- **Phase 6 仍缺横向**：势力↔势力之间的传播、情报网络没有。
- **Phase 7 其余与 §46 一致地不做**：Inference / Bias / Memory Reconstruction / 复杂心理模型
  是方案自己划到第一阶段之外的东西，未实现属于守约而非欠债。
- **§23 的行动规则内容未填**：`beliefActions.rules` 空着是刻意的——「什么信念导致什么行动」
  属于游戏设计而非机制缺口；这一步不通之前，信念只影响推演提示词，不会自动触发世界动作。
- **检索只回本人记忆**：跨角色的公共知识（如"王都在北方"）尚无注入路径。
- **Evidence 未与调查系统打通**：`systems/law/Investigation` 仍直接读感知表，未改为读记忆。
- **归档条目只增不删**：压缩把原条目降级为 `archived`（退出检索但保留存档），没有清理通道。
- **死者仍会传话**：没有 NPC 死亡模型，`gossipTick` 只跳过世界书里不存在的 id。
- `visibility` 的 `faction` / `party` 共享通道尚未实现：它目前只决定「能否被转述」。
