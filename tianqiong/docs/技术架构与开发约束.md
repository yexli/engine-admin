## 2. 依赖方向（ESLint 强制，越界即 error）

```
types ← data ← core ← ai / repo ← store ← ui
                    ↑____________|
```

| 层 | 允许依赖 | 禁止 |
|---|---|---|
| types | 无 | 一切 |
| data | types | core/ai/ui |
| core | types, data | React、zustand、DOM、localStorage、UI |
| ai | types, data, core(只读) | React、UI、repo |
| repo | types, core/ports | React、UI、ai |
| store | core, types | 直接改 WorldState |
| ui | core(经 index), ai/gateway, store, data, types | 改 WorldState（必须发 GameCommand） |

## 3. 核心数据流（§42/§43 铁律）

```
用户/AI 意图
   ↓ GameCommand（engine.dispatch 唯一入口）
规则校验（前置条件在 core 函数内判定）
   ↓ WorldState 突变（core.S / core.CB）
事件总线 bus.emit({type:'changed'|'toast'|'sheet'|'check'|'combat'|'foeHit'|'screen'})
   ↓ attachCoreBridge（store 镜像为 rev 等 UI 信号）
Zustand → React 重渲染
   ↓（每次改写后 save() 经 SavePort 落盘）
Repository → localStorage（未来 → SQLite）
```

**AI 永远不能直接改状态**：`ai/ruleSim` 只返回文本与判定（`narrative`/`npcDecide`/`contextLayers`）；后果（好感、通缉、记忆）全部由 core 执行。

## 4. 存档与数据契约

- 运行时状态 = `WorldState`（types/world.ts），`ver:1` 为存档版本字段，结构演进必须做迁移函数并保持旧档可读。
- 存档介质由组合根按运行环境选择（main.tsx）：浏览器 = localStorage（键 `tq2_world_v1`）；
  Tauri 壳 = SQLite（`sqlite:tianqiong.db` · `saves(id,ver,updated_at,payload)` 整包 JSON 落库，
  迁移在 `src-tauri/src/main.rs` 声明，`SqliteRepository` 走「内存镜像 + 串行写穿队列」满足同步契约）。
- 导出/导入仍为整包 JSON（系统面板），两种介质格式同构可互导。
  热数据拆表（npc_memories/world_events/history）留待查询需求出现时做。

## 5. AI Gateway 接口契约（已接入真实模型 · 配置驱动热切换）

```ts
interface AiPort {
  provider: string;
  narrative(kind: string, p: { loc: string }): string;      // 同步：场景/氛围文本（只产文本）
  narrativeAmbient(): string;
  npcDecide(npcId: string, req: NpcReq): NpcVerdict;        // 同步：规则档位
  contextLayers(s: WorldState, h: AiHelpers): [string, string[]][]; // §51 八层上下文
  /* 可选异步通道（openaiCompat 实现；缺省 = 纯规则路径） */
  intentAsync?(text, ctx): Promise<{ intent; target? } | null>;      // Intent AI
  narrativeAsync?(kind, p): Promise<string | null>;                  // Narrative AI
  npcDecideAsync?(npcId, req, ctx): Promise<NpcVerdict | null>;      // NPC AI（含台词）
}
```

- **三通道落地**：自由文本意图解析（LLM 优先、正则兜底，日志标 `〔意图解析·LLM〕`）；
  场景叙事（异步生成 + `✦ AI 叙事` 角标，按 `loc:day` 缓存）；NPC 请求权衡（「沉吟」演出 →
  六档判定校验 → LLM 台词优先、台词池兜底，权衡卡标 `·LLM`）。
- **参数包契约（G1-G6 · 自由行动 2a/2b）**：
  G1 结构化通道 = 枚举意图 + 参数包（`target/dest/focus/topic`）+ 自由文本槽（`steps` 顺序分解 ≤3，
  检定步后按演出节奏串联、战斗爆发截断）；枚举覆盖不了时带原文交规则层二次匹配，禁止静默丢弃；
  G2 LLM/正则双通道**参数同构**（`intentAsync` 与 `parseRegex` 产出同一 `IntentParse`），降级路径行为一致；
  G3 参数解析收敛在 `executeIntent` 汇合点（`resolveTarget`/`findLoc`），禁止各 case 自解文本；
  G4 **UI 文案 = 能力承诺**：placeholder/提示示例句必须可执行；
  G5 玩家指明细节（focus/topic）必须在叙事输出中被回响（echo 行），适用于一切叙事出口；
  G6 测试随 schema 泛化：复合/缺席/越界/降级同构用例常驻 `core.test` 意图组。
  chip 展示 = 意图名 + 关键参数（如 `打听·米娅`、`前往→银鸥酒馆`），focus 不进 chip 防信息过载。
- **聊天窗口（第四通道 · chat）**：dlgOpts 入口统一「聊天」→ 独立窗口（气泡历史/话题 chips/输入胶囊，
  样式在 `styles/chat.css` 新文件，不碰冻结 app.css）。`chatCtx` 关系包 = **唯一关系读取组装点（G8）**：
  att 门禁档（hostile 拒开/在场校验/warm 话题需友好）+ rels 牵扯 + 势力立场 + 日程 act + 记忆 + 近 6 轮历史；
  `chatAsync` 只回 `{line, attDelta, mem, rumor}`，后果由 core `applyChat` 白名单落地
  （attDelta clamp [-2,2] + 日封顶：同 NPC ≤+2、全局 ≤+4；rumor 走 spreadRumor 沿 rels 一跳；
  每 3 轮玩家发言 advance(1)）。历史入 `WorldState.chats`（可选字段，每 NPC ≤20 轮，懒初始化旧档可读）。
  降级：`ruleSim.chat` 三档池 + interest/goal 模板 + 上句去重（G2 同构）。
- **人设锚（G7）**：`ai/persona.ts` 的 `personaBlock(npcId)` 组装姓名/头衔/种族/志向/关切/底线，
  **所有 NPC 类 AI 通道共用**（chatAsync / npcDecideAsync），禁止在适配器内各自拼 prompt；
  内建 NPC 人设字段（people.json）必须进 prompt——修复台词漂移根因。
- **后果收敛（G9）**：AI 对话输出 = 台词 + 有界判定（attDelta/mem/rumor），后果一律由 core 单一写入口落地
  （白名单 + clamp + 日封顶防刷）；羁绊判定不依赖 AI——赠礼/赔罪/仇怨为纯规则层。
- **新 NPC 零代码契约（G10）**：people.json 字段（人设/topics/faction/likes/intimacyGate/reciprocate）
  齐备 → 聊天/请求/叙事/赠礼四个交互面自动可用；缺省字段由 interest/goal 推导，fixture 断言作门禁。
- **羁绊系统（卡 11 · G11-G12）**：关系三层化=好感轴 + 亲密度档 + 仇怨状态，单一事实源 `bondOf(id)`
  （G11：UI/聊天/请求门禁/商店计价全走此口）。
  赠礼五档（loved+8/like+5/neutral+2/dislike-3/hated-8）× quality 倍率（稀有以上按 2 封顶）、
  单礼 clamp ±10、同 NPC 日≤2 周≤6；连带 propagateAtt：|rels 边|≥30 邻接按 Δ×val/100 同调 clamp ±2。
  亲密度：att≥80 + gate（quest/flag/gifts/chats）→ 挚友/知己/结义；att<60 或仇怨期权益冻结不退档；
  权益=私密话题常在/请求利益+1/回赠池开启/称号徽章。仇怨：重事件触发（行凶/告发 sev3、威胁 sev2），
  后果=拒收礼+拒请求+商人价+25%（sev3 拒售）；化解=赔罪（魅力检定+补偿金 100×sev → sev-1、att+15，
  出口常驻防死锁）；sev1/2 每 20 天降一档，sev3 长记忆。回赠/衰减挂 newDay（`bondDailyTick`，
  置于 economy 回归之后）。防刷三 cap（G12）：聊天 +2/+4 日封顶、赠礼日周封顶、连带 clamp ±2。
- **降级铁律**：任何 LLM 失败/超时/越界输出 → 返回 `null` → core 走规则模拟路径，
  并 toast 提示「已降级规则模拟」（30s 节流）。状态改写永远只在 core。
- **配置**：系统面板「AI 网关」卡（baseURL/model/key/开关，localStorage `tq2_ai_cfg_v1`，
  默认 DeepSeek `https://api.deepseek.com/v1` + `deepseek-chat`，兼容任意 OpenAI 协议端点）。
  保存即热切换（`gateway.reload()`），带连通性测试。
- 新增模型 = 新适配器实现 `AiPort`；**禁止**在 core/ui 里直接 `fetch` 模型。
- 上下文分层由 `AiHelpers`（`ai/helpers.ts`）注入只读查询，禁止适配器 import store/ui。

## 6. 禁止事项（红线）

1. 禁止 React 组件/hook 直接改 `core.S` / `core.CB`（DEV 桥 `__tq` 仅限脚本自检）。
2. 禁止在 core import `react`/`react-dom`/`zustand`/`@/ui/*`/`@/store/*`（ESLint 报错）。
3. 禁止把游戏规则写进世界书 JSON（data 层零逻辑），也禁止把世界观文案硬编码进 UI。
4. 禁止 AI 输出直接落库/改状态——必须经 `dispatch(GameCommand)`。
5. 禁止绕过 `check()` 演出节奏的同步化改法（调度器可注入，但生产路径保持 1450ms/520ms 原型节奏）。
6. 禁止手改 `src/styles/app.css` 中来自原型的规则观感（结构/色值/动效）——观感变更需先在原型/设计稿定稿。
7. 禁止用 `any` 吞掉类型（warn 级，评审时按缺陷处理）。

## 7. 测试规则

- 命令：`npm run typecheck` / `npm run lint` / `npm test` / `npm run build`（四绿才可提交）。
- core 单测必须确定性：`rng.seed(n)` + `scheduler.inject(同步)` + `MemorySaveRepository`（见 `src/core/core.test.ts` 模式）。
- 涉及 UI 观感的改动，跑 `node scripts/shot.mjs <url> <outDir>` 出双端截图对照。
- **Tauri 窗口截图勿用 GDI**（WebView2 GPU 合成会截出空帧）：以
  `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9223" npm run tauri dev`
  启动后跑 `node scripts/shot-tauri.mjs <outPng>`（CDP screencast 抓真实画面）。
- 新增系统模块时，至少覆盖：正常路径 + 边界（金币为 0 / 通缉封顶 / 缺图回退）。
