## 一、这次解决了什么

编织（Narration）是迁移里最别扭的一块：按 §30 它是表现层（"玩家应该看到什么"），
但本地实现经 `mutate.weaveLogs` **改写状态**——session 档里这么做会被下一次快照
冲掉。本次把它彻底归位：

```text
快照回灌（bus changed）
    ↓ 水位差分：id > watermark 的新见闻
一批一织：gateway.active().narrateAsync(事实, 五层上下文)
    ↓ 织后正文
覆盖表 Map<logId, text|''>   ← 状态零改动（快照随便刷，覆盖按 logId 幸存）
    ↓ 渲染叠加
SceneView.visibleLog：锚点条目替换为织后正文（cls 'ai'，带 ✦ AI 标），
被吸收的条目隐藏——与本地 weaveLogs 的合并语义、玩家原话行保留铁律一致
```

与本地实现的语义对照：

| 语义 | 本地 Narration | sessionWeave |
|---|---|---|
| 触发 | 命令出口新见闻 | 快照回灌后水位差分 |
| 合并 | weaveLogs 改写状态 | 覆盖表（锚点替换 + 其余吸收） |
| 玩家原话「＞ …」 | 保留 | 保留（同一条铁律） |
| 窗口期隐藏 | weave 描述符 | 同一信号复用 |
| 失败保底 | 规则原文照常 | 同 |
| 换代 | epoch 作废 | log id 回退检测 → 覆盖清零 |
| 能力门 | port.narrateAsync | 同（ruleSim 或真模型皆可） |

改动面：`src/plugins/sessionWeave.ts`（新，~150 行）+ `SceneView.visibleLog`
一处 flatMap + `main.tsx` session 档装配。本地/bridge 档覆盖表恒空，渲染原样通过。

## 二、测试证据（新增 5 用例，全量 128 文件 / 1771 用例全绿）

| 用例 | 断言 |
|---|---|
| ① 一批一织 | 锚点替换为织后正文（cls 'ai'）且恰一条；其余吸收；原话行保留 |
| ② 水位 | 第二条命令只织增量（旧条目不重织） |

| ④ 无能力 | 端口无 narrateAsync → 完全不织 |
| ⑤ 换代自愈 | 新局 log id 回退 → 上一局覆盖无残留 |
