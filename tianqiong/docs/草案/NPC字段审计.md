# NPC 字段审计（NpcDef）

> 方法：对每个字段做两次检索——① 生产代码的属性访问（排除 `*.test.ts`）；② 124 条数据（档案 109 + 街头 15）的填充率。
> 结论均可复核，命令见文末附录。

---

## 0. 三句话结论

1. **能立刻删的只有 3 个**：`tier`、`owner`、`age`——生产代码零消费者，其中 `tier` 连注释都标了 @deprecated。
2. **最大的一块不是"多余"，是"没接线"**：`lore` 八项、28.4k 字、109/109 全填，**游戏里没有任何一处读它**（AI 不读、面板不读）。要么接上，要么整块删掉。
3. **最伤的一处是"接了线却没数据"**：`interest`、`bottomLine` 等 6 个字段机制在读，但档案 109 人**全是 0 填充**——所以 AI 拿到的"人设锚"里，"关切"和"底线"两行对 109 个人永远是空的。

## 2. 问题一：三个能立刻删的字段

**`tier`** —— 语义已被 `worldImportance`（静态）× LOD（动态）取代。数据 124/124 全填，取值只有 1/2/3（按境界派生）。项目自己已经写了守护测试：`contextProfile.test.ts:199`「世界书里不再有任何地方读取旧 tier」。

> 删除要连带改一处：`npcArchive.test.ts:118` 把 `tier` 列在"必需机制字段"里（`['sv','color','tier','hours','loc','greet']`）。数据与断言一起删，测试仍绿。

**`owner`** —— "所属"原文。UI 层对 `owner` 零命中，全库属性访问只有 `capabilities.owner`（动作归属系统，同名不同物）。109 条数据填着，没有人读。

**`age`** —— "设定年龄"。UI 零命中，测试零依赖，89/109 填着没人读。

> 这三个删除的收益不在性能（字段本身很小），在**消除歧义**：后来者看到"必有字段"会以为它有机制含义，于是继续往里填。

---

## 3. 问题二：`realm` / `realmTier` / `sourceNo` 的三个出路

这三个字段的处境和 `tier` 不同——它们**被数据护栏用着**：

`npcArchive.test.ts` 用 `realmTier` 做台阶校验（1–6 合法、8 位神格层面必须留空），用 `realm` 原文核对台阶推导是否自洽（`WORDS[t].test(head)`）。

也就是说：**它们是"生成器质量护栏"的输入，不是给玩家的**。

- 如果你打算继续从 md 生成/维护 NPC 数据 → **保留**（护栏值这份钱）
- 如果这批数据就此冻结、不再生成 → 可以删（护栏也一并删）
- `sourceNo`（档案编号）：**建议留**。成本是一行数字，换来的是"数据可疑时能一对一核回 145 KB 的原始档案"这条溯源链。

---

## 4. 问题三：`lore` —— 最大的一块，也是最尴尬的一块

- 数据侧：**109/109 全填，七项合计 28.4k 字**（档案正文最丰富的一部分）
- 消费侧：**生产代码零命中**。UI 层零命中。AI 层零命中（`personaBlock` 不读它；`matchLore` 读的是 `lore-person.json` 的 canon，不是这份）

同源数据还有两份：`docs/设定源/天穹纪-人物.md`（原文 145 KB）与 `src/data/lore/lore-person.json`（每人 300 字截断 canon，124 KB）。

**`lore-person.json` 是纯派生物，已验证**：用它自己的字段拼装——

```text
拼装：所属：圣辉帝国（中央大陆）· 皇权派 身份 御前侍从长… 种族·年龄·性别 人类 / 33岁 / 男
原文：所属：圣辉帝国（中央大陆）· 皇权派 身份 御前侍从长… 种族·年龄·性别 人类 / 33岁 / 男
```

前半逐字一致。它完全可以由 `npc.json` 在运行时拼出来，而且拼出来的是**完整版**（现文件是 300 字截断版）。

> 于是这里有一个组合决定：**接线 `lore` → 顺手就能省掉 124 KB 的派生文件与"两份真相"**（改档案件自动生效）。
> 反之，若决定不做 NPC 立体化 → `lore` 这一整块（28.4k 字）就是可以删掉的最大一块死数据。

## 5. 问题四：六个"有人读没人填"的字段

`interest` / `bottomLine` / `likes` / `dislikes` / `intimacyGate` / `reciprocate`

- 街头 15 人：**全部填满**
- 档案 109 人：**全部为 0**

后果是具体的，不是理论的：

| 位置 | 现在的实际行为 |
|---|---|
| `personaBlock` | 对 109 人只拼出 7 项（姓名/头衔/种族/志向/说话习惯/优先序/拒绝方式）——**"关切""底线"两行永远缺席** |
| `ruleSim.chat` 的模板句 | `seeds = [interest, goal]` → 对 109 人只剩 goal 一条腿 |
| `Bond.giftPicker` | 无 `likes` → 全靠 `deriveTag` 按物品名猜 |
| `Bond.intimacyUpOk` | 无 `intimacyGate` → 109 人用同一套默认门槛 |

**这才是"109 个档案人物不如 15 个街头 NPC 好聊"的机制层原因**：机制是照街头 15 人的字段设计的，109 人只填了另一半。
