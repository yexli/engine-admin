# NPC 字段清单（逐字段释义）

> 分两类，**别混**：
> · **世界书字段（NpcDef）**——写在 `src/data/npc/**/npc.json` 与 `people.json` 里，是"设定"，**可以删改**（删了不影响旧存档）。
> · **运行时字段（NpcDynamic）**——写在存档里，是"状态"，**删要写迁移**。
>
> 例子取自两个真人：**凯尔**（档案人物，中央 · 皇权派首领）与 **「灰烬」**（街头 NPC，深巷里的无名者）。

---

## 一、身份与展示（7 个）

| 字段 | 是什么 | 凯尔的值 | 谁在读 |
|---|---|---|---|
| `name` | 姓名。对话气泡、面板、日志里都靠它 | 凯尔 | 全引擎 |
| `title` | 头衔。跟在名字后面的一行身份 | 皇权派首领 | UI |
| `race` | 种族（十三族之一），影响战斗与称呼 | 人类 | 战斗/UI |
| `gender` | 性别。**唯一用途是婚配判定**（婚龄分男女两档） | male | Rites / Deity |
| `sv` | 头像上的那个单字（SV = 单字） | 凯 | UI 头像 |
| `color` | 这个人的主题色，头像底色与名字用它 | #b8912f | UI |
| `worldImportance` | 世界重要度 0–4：**"不考虑玩家，这个人在世界本身有多重要"**，决定 AI 上下文预算上限 | 2 | Chat / Dialogue / ContextBuilder |

---

## 二、位置与作息（4 个）

| 字段 | 是什么 | 凯尔的值 | 谁在读 |
|---|---|---|---|
| `loc` | 常驻地点 id（必须是已登记地点，有测试校验） | palace | Npcs / Dialogue |
| `hours` | 出没时段 `[起, 止]`，时辰序号 0–12（可跨子夜） | [0, 12] | `Npcs.npcAt`（没有 schedule 时的回落） |
| `schedule` | **更细的日程**：一天切几段，每段「在哪、在做什么」。有它时 hours 被短路 | 0–4 回府歇下 / 4–12 朝会与政务 | Npcs / 日结算 |
| `needFlag` | 出现条件：玩家拿到这个 flag 才见得到他 | 凯尔没填 | Npcs（门禁）/ Shop |

> `needFlag` 全库只有一个人用：**奥托**（药剂商人）→ `caravan_evt`，商队事件发生后才出现。
> `schedule` 里那个 `act`（"朝会与政务"）不只是装饰——对话时会当作"你正在做什么"喂给 AI。

## 三、对话与人设（8 个）

| 字段 | 是什么 | 凯尔的值 | 谁在读 |
|---|---|---|---|
| `greet` | **三档问候**，点开对话的第一句；按好感选档 | cold「阁下有事？」neutral「请坐，茶还热着。」warm「来得好——这盘棋，正缺个看得懂的人。」 | Dialogue |
| `goal` | 人生目标：他在做什么、想要什么 | 表面推动"皇权法案"，实际在编织贵族院—军方—商邦的通路——他要的从来不是皇权，是"皇帝之后我说话算数" | persona / ruleSim / UI |
| `interest` | 关切/利益：他在意什么 | **凯尔没填**（109 个档案人物全没填） | persona / ruleSim |
| `bottomLine` | 底线：什么他不做。触碰它 = 拒绝/敌意 | **凯尔没填** | persona / UI |
| `voice` | 说话习惯：语速、停顿、口头禅 | 野心外罩礼貌，行动如棋手；记仇，但只记"该利用的仇" | persona |
| `priority` | 优先序：多目标冲突时先保哪个 | 表面推动法案 → 实际编织通路 → "皇帝之后我说话算数" | persona |
| `refuseStyle` | 拒绝时的性格六型：direct 直率 / stout 烈性 / smooth 圆滑 / cold 冷淡 / principled 原则 / rational 理性 | direct | persona / ruleSim |
| `topics` | 话题钩子，聊天窗口里那排可点的话题 | 皇权与殿权 / 军机处的动向 / 皇帝不肯说的那件事(warm) | Chat（chips）/ Dialogue |

> `topics` 的每一条只有 `l`（标签）和 `tier`（safe 常在 / warm 需友好）。**标签后面没有内容**——玩家点它，等于把标签当一句话发给对方。

## 四、关系与势力（2 个）

| 字段 | 是什么 | 凯尔的值 | 谁在读 |
|---|---|---|---|
| `rels` | NPC↔NPC 的**有向关系边**：`{对方id: {type, val}}`，val 是 -100..100 的强度 | herman: kin 30（皇帝）/ seris: rival -25（赛瑞斯）/ vik: ally 25 / duke: ally 25 | Relations / ContextBuilder / Bond |
| `faction` | 所属势力，作用于声望、价格、立场摘要 | empire | 14 个文件（经济/学院/声望…） |

> 全库关系类型分布：`ally` 306 条 · `rival` 66 · `court` 18 · `kin` 6 · `faith` 4 · `enemy` 3 · `mentor` 1。人均 3.7 条边。

## 五、羁绊与赠礼（4 个）

| 字段 | 是什么 | 「灰烬」的值 | 谁在读 |
|---|---|---|---|
| `likes` | 喜欢的**赠礼标签**（物品分类，不是具体物品） | rare（稀有）、gem（宝石） | Bond（赠礼反应） |
| `dislikes` | 讨厌的赠礼标签 | relic（遗物） | Bond |
| `reciprocate` | **回赠池**：亲密度升档时他会回送的具体物品 id | venom_gland（毒腺） | Bond |
| `intimacyGate` | 亲密度升级门槛：任务 / flag / 赠礼数 / 聊天数 + 一句说明 | gifts 4、chats 12、"阴影里的人，话要一句句换" | Bond |

> 这一组**街头 15 人全填，档案 109 人全空**——所以 109 个人的赠礼偏好全靠按物品名猜，升级门槛全用默认值。

## 六、档案元数据（6 个）

| 字段 | 是什么 | 凯尔的值 | 谁在读 |
|---|---|---|---|
| `sourceNo` | 《天穹纪-人物》档案编号 001–109，追溯用 | 003 | 无人（数据侧溯源凭据） |
| `owner` | 档案里的"所属"原文一行 | 圣辉帝国（中央大陆）· 皇权派 | **无人**（UI 零命中）→ 可删 |
| `age` | 设定年龄（**不是**运行时年龄） | 33 | **无人**（代码里的 `age` 都是玩家年龄）→ 可删 |
| `realm` | 境界**原文**，完整保留注解不截断 | 正式级巅峰（剑术精湛，已触及主教门槛） | 只有数据护栏测试读 |
| `realmTier` | 境界**档位**：1 信徒 / 2 见习 / 3 正式 / 4 主教 / 5 圣阶 / 6 神阶 | 3 | 只有数据护栏测试读 |
| `tier` | **旧的重要度档（已废弃）**。语义已被 worldImportance × LOD 取代 | 3 | **无人** → 可删 |

> 神格层面的人（主神、冥府之主）**故意留空 realmTier**——"那是神格本身，不是修行到的阶"，混进同一条轴会让"圣阶·极"和"冥府之主"看起来只差一级。

## 七、人物志正文 `lore`（8 个子字段）

**整块 109/109 全填、合计 28.4k 字，但游戏里没有任何一处读它。**

| 子字段 | 是什么 | 凯尔的值 |
|---|---|---|
| `keywords` | 检索关键词（人物志与大世界检索共用） | 凯尔、皇权派、御前大臣、圣辉城、贵族院、皇帝之心腹、皇家侍从长 |
| `identity` | 身份：一句话说清他在世界里的位置 | 御前侍从长、皇权派首脑、贵族院新贵的实际领袖——帝国二十年里蹿升最快的年轻人 |
| `appearance` | 外貌 | 黑发利落，眉间一道浅疤，笑起来却温文；常着深蓝常服，不佩剑入宫，腰间藏一把短匕 |
| `personality` | 性格 | 野心外罩礼貌，行动如棋手；记仇，但只记"该利用的仇" |
| `abilities` | 能力（叙事性描述，不是技能表） | 宫廷礼仪与密语速记、贵族联姻网的布局、剑术（贵族院比试连续三届魁首） |
| `past` | 过往 | 平民勋爵之子，十四岁入宫为伴读；靠三段棋局和一场政变前的"提前站队"赢得赫尔曼信任 |
| `flaw` | 弱点与把柄——玩家可下手的钩子 | 知道屠村密事，但从未说出口；个人财政靠联姻维持，有笔黑账 |
| `belongings` | 持有物（叙事性；真要进背包走 NpcDynamic.bag） | 祖父的旧怀表（他唯一的软肋物品）、短匕"刺冬" |

## 八、运行时字段（NpcDynamic · 存在存档里，**不是**世界书）

| 字段 | 是什么 |
|---|---|
| `att` | 好感 -100..100（对话、赠礼、事件都在动它） |
| `mem` | **@deprecated** 老记忆表，只作旧档迁移载体 |
| `met` | 是否正式见过面（影响问候与图鉴） |
| `rels` | 关系边的运行时投影（从世界书种子初始化后随事件变化） |
| `chatDay` | 聊天好感的当日增益（日封顶 +2，防刷） |
| `intimacy` | 亲密度 0–3（挚友/知己/结义），好感 ≥80 且过 gate 才升 |
| `bondProg` | 升档门计数：赠礼数 / 聊天数 / 完成任务数 |
| `grudge` | 仇怨：何时结、为什么、严重度 1–3（3 级不会消退） |
| `giftDay` | 赠礼日/周封顶计数（≤2/日、≤6/周） |
| `giftKnown` | 已发现的偏好标签（赠礼后才在人物志里显式呈现） |
| `goal` | 世界推演赋予他的行动目标（带来源事件，可追溯） |
| `bag` / `gold` | NPC 自己的物品栏与钱包——**字段已留，玩法未接** |
| `effects` | 状态效果（add_status / remove_status 的落点） |

## 附 · 两个真人长什么样

**凯尔（档案人物）**：38 行 JSON，带 `sourceNo/owner/age/realm/realmTier/lore` 这六样档案专属字段，**没有** `likes/dislikes/intimacyGate/reciprocate/interest/bottomLine`。

**「灰烬」（街头 NPC）**：同样 30 多行，**没有** `lore` 与档案元数据，但**有全套** `likes/dislikes/reciprocate/intimacyGate/interest/bottomLine`。

> 一句话：**两拨人各拿一半字段**。这不是设计意图，是两批数据由不同流程产出的结果——
> 街头 15 人是手写的"机制优先"数据，109 个档案是脚本从 md 搬来的"叙事优先"数据。
> 而引擎目前只认机制那一半。
