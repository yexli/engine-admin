## 第一部分 · 代码审查结论

### P0 —— 会出错（3 项，均在迟到事实通道与会话恢复）

| # | 问题 | 位置 | 触发场景 | 修法一句话 |
|---|---|---|---|---|
| 1 | **SSE 干净断流后永不重连**：流正常结束（done）不回调 onError，`closeStream` 非 null 挡住重启；重连职责被推给在线探活，而探活在 `online===true` 时直接 return；轮询兜底 `eventsSince` 未在生产接线 | gameSession.ts:158-160 + extSession.ts:140-144 | 宿主优雅断流、代理/防火墙空闲回收连接 → 迟到事实通道永久静默（聊天回话无声消失） | done 路径也走 onError；extSession 对流做独立指数退避重连（不等整体 offline） |
| 2 | **首连以 after=0 全量重放事件环**：刷新页面后 `startStream(after=0)` 把环里最多 1000 条陈旧事实（含 `screen:'game'`、toast、sheet）灌进 `core.S===null` 的空客户端——旧 screen 事件把 store.screen 置 'game'，而 App 的 `inGame = screen==='game' && !!core.S` 为 false → **生产构建白屏且无任何可点元素** | extSession.ts:130-132 + game-host.ts 事件环 | 页面刷新 / 新开标签 + 宿主已运行一段时间 | 首连握手用 `/game/health` 的 `lastSeq` 作流起点（只听"从现在起"），投影恢复走 `/game/state`（见 #2' 联动设计） |
| 3 | **宿主重启后 `_seq` 归零，客户端水位单调不减 → 此后所有迟到事实被永久去重** | extSession.ts:135 vs game-host.ts eventSeq 从 0 重计 | 宿主重启（开发常态/部署更新）而页面不刷 → 聊天回话、日结算等异步延续无声消失（命令响应不受影响，极难察觉） | 握手对齐：每次转 online 时用 health 的 `lastSeq` 重置客户端水位；长期方案 `_seq` 带启动代次 |

**P0 联动设计（一次改动修三条）**：把"探活成功"升级为"会话握手"——
`health()` 拿 `lastSeq` → `lastSeq = health.lastSeq`（重启代次归零问题消失、
首连只听增量）→ `state()` 拉快照，若非空则回灌并 `screen:'game'`（刷新即回到
进行中的局）→ `startStream(after: lastSeq)`。流断开（含 done）→ 独立的重连
监督器指数退避重开流，重开时重新握手。

### P1 —— 边界条件会咬人（4 项）

| # | 问题 | 位置 | 触发场景 | 修法一句话 |
|---|---|---|---|---|
| 4 | **命令事实双通道重复应用**：宿主在 dispatch 期间就把事件推 SSE（先于响应入网），SSE 先应用一遍，响应到达后 `apply(res, true)` 无条件重放 → toast 双份、浮层双闪 | extSession.ts apply 重放无 `_seq` 过滤 | 常态（SSE 在线时的每条命令） | apply 重放前按 `e._seq > lastSeq` 过滤（advanceSeq 照做） |
| 5 | **命令无客户端排队**：双击/连点使多个 POST 并发在途，响应体大小差异可致后发先至——旧快照整体回滚新状态，且 logSeq 回退被 sessionWeave 判成"换代"→ 清空覆盖表 + 重织 | extSession sendCommand + sessionWeave 换代检测 | 双击、连点 | 客户端命令串行化（promise 队列），或快照带单调 epoch、apply 丢弃过期 |
| 6 | **命令超时被当断线但服务端已生效，且无幂等键**：15s 客户端中止后按提示重发即双重执行（扣两次钱） | gameSession 超时 + /game/command 无 commandId | 慢命令（>15s）超时 | 命令带客户端幂等键，宿主对重放命令返回既有响应（LRU） |
| 7 | **本机 CSRF**：不校验 Origin/Content-Type，玩家浏览器里的任意网页可用 `text/plain` 简单请求 POST `/game/command`、`/game/new`（写操作可执行，仅响应不可读） | game-host 路由 | 恶意网页 + 宿主运行中 | 校验 Origin 为空或本机白名单，或要求自定义头（触发预检） |

### P2 —— 隐患（5 项）

| # | 问题 | 修法一句话 |
|---|---|---|
| 8 | 双环上限静默 shift（captured 800 / ring 1000）：单命令 >800 事件响应缺事件；断流窗口 >1000 补发缺口无标志 | 响应带 `fromSeq`，客户端检缺口触发 eventsSince 全量补齐 |
| 9 | **TopBar 读面切换是死分支**：session 档 report 从不写 `tick/day`，`extReady` 永 false（显示数值碰巧由快照兜住，`t.day ?? 1` 的兜底掩盖了接线缺失） | report 补 tick/day（从 res.t / health.time），或删死分支明确走投影 |
| 10 | config：`{"enabled":"false"}`（字符串）/`0` 两个分支都不命中 → 落到默认开；损坏 JSON 静默开 | enabled 只认布尔真值，其余视为配置损坏并 warn 落默认 |
| 11 | WorldEngineClient（SDK 件）：WS key 走 `?key=` 查询串（进代理日志）；backfill 与 live 乱序（bridge 档遗产，当前非主路径） | 文档标注 + 后续升级 WS 鉴权头 |
| 12 | sessionWeave：覆盖表无界累积（仅换代清零）；水位在能力检查前推进——玩家中途配好模型，历史条目永不补织 | 随快照回收窗外 logId；能力就绪后允许近窗补织一次 |

**审查确认无问题的核对项**：narrateAsync 有超时控制、weave 描述符无永久卡死路径
（try/finally 恒清）、`/game/command` 同步段在 Node 单线程下无撕裂、tmp+rename
原子写、visibleLog 的 memo 依赖与 'changed' 合帧联动正确、App 的 `!!core.S` 门
挡住了空投影下的崩溃（代价即 P0-2 的白屏）。

## 第二部分 · 遗留问题处置方案

### M1 · P0/P1 修复（预计 1 个工作段落，~6-8 处小改动）

| 项 | 内容 | 验收 |
