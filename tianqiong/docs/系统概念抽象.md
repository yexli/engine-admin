## 0. 抽象骨架

### 0.1 四个本体

整个项目只有四种东西在流动。所有系统都可以按「它产出哪一种、消费哪一种」定位。

| 本体 | 载体 | 唯一权威 | 关键约束 |
|---|---|---|---|
| **事实** | `WorldState`（运行时）+ `WorldEvent`（历史） | `core.S`（world/WorldState.ts:15-20） | 写入只经 `mutate` 原语（world/WorldMutate.ts:27） |
| **认知** | `knowledge`（感知）/ `memories`（记忆）/ `beliefs`（信念） | 各 NPC 自己，不是世界真相 | World Truth ≠ NPC Knowledge（events/Perception.ts:3） |
| **规则** | 判定函数 + `rng` + `DiceEngine` | 纯函数、可复现 | AI 不得生成骰值（dice/DiceEngine.ts:3） |
| **意图** | `GameCommand` / `IntentParse` / `ConsequencePlan` | 由外部提出、由 core 裁决 | Action ≠ Event（events/EventSchema.ts:5） |

「事实」与「认知」的分离是这个项目最核心的一次抽象：世界史记客观发生了什么，感知表记谁知道这件事，记忆表记他记得什么样子，信念表记他由此相信什么。四者依次派生、允许全部失真。

### 0.2 三条通道 + 一条信号线

| 通道 | 载体 | 方向 | 谁在用 |
|---|---|---|---|
| **命令通道** | `GameCommand` → `dispatch` | 玩家/UI → 世界 | 玩家操作（`internal` 能力） |
| **事件通道** | `worldBus`（`WorldEvent`） | 系统 ↔ 系统 | 已发生的事实传播 |
| **推演通道** | `ConsequencePlan` → 双闸校验 → 执行器 | 世界 → AI → 世界 | L3 与升格后的 L2 事件 |
| 信号线（非通道） | `bus`（`CoreEvent`） | 引擎 → 界面 | 渲染、浮层、toast |

两条总线互不干扰，是这个项目最容易搞混、也最不能搞混的一处（events/EventBus.ts:146-152）。

### 0.3 系统的两级含义

「系统」在本项目里同时指两件事，抽象时必须分开：

1. **插件意义上的系统**——在 plugins/systems.ts 登记过能力的那一个。2026-09 收敛后共 **19 条**（收敛前 24 条：commnet → travel、culture + rites → customs、adventuring → quest、codex → academy，naming 降级为规则模块，world 改名 world_facts）：
   character / npc / combat / quest / inventory / economy / faction / relationship / reputation / law / travel / religion / academy / dungeon / starnet / dialogue / timeslip / customs / world_facts。
2. **模块意义上的系统**——`src/systems/<域>/` 下的一个实现文件（23 个域目录、47 个 .ts）。

两者不是一一对应：`systems/combat` 目录只有一个 `Combat.ts` 却登记了 5 条 internal 能力；`systems/travel` 一个文件同时承载路线、地标、险区、城内可达性四组概念。**能力登记表才是对外契约，目录结构只是文件组织。**

## 1. 基础设施

基础设施的共同特征：它们不认识任何具体玩法，只提供机制。删掉任意一个业务系统，基础设施照常工作；反过来则不成立。

### 1.1 WorldState —— 唯一事实来源

- **内核**：装世界的一切可持久化事实，并规定它怎么出生（`newState`）、怎么被旧档读回（`hydrate`）、怎么落盘（`save`/`sync`）。
- **容器**：`core.S`（世界）/ `core.CB`（战斗，不落档）/ `core.curShop`（商店游标）（world/WorldState.ts:15-20）。`need()` 在未开局时抛错，是所有系统取状态的统一姿势（:40-43）。
- **结构演进**：`ver` 保持 1，新字段一律可选 + `hydrate` 补默认，因此旧档始终可读（:149-248）。文档里「第一阶段不用做迁移函数」的写法在这里被具体化为一条硬规矩：**缺失放行、存在即校验**（validation/RuleValidator.ts:23-25）。
- **序号必须随档走**：`evtSeq`/`logSeq`/`memSeq`/`isq` 四类自增序号全部入档，缺一个就会在重开后撞 id（:152-156、:168-175、:222-235）。
- **落盘节流**：`sync()` 立即广播 UI，写盘走 100ms 尾节流（:262-283）。

### 1.2 WorldMutate —— 受控写入原语

- **内核**：世界状态的**唯一**写入实现点（world/WorldMutate.ts:1-5）。它只依赖 WorldState / WorldClock / 事件总线的纯工具 / 世界书，零系统依赖——这样被写入层独立出来，才不会有 `Gains → WorldAPI → WorldRuntime → Gains` 的近距循环（:7-10）。
- **分工**：`mutate` 管字段（+1 金币、扣 3 点血），`execute` 管世界动词（有因果依据、要留 reason 与因果链）（:11-14）。
- **原语面**：玩家侧 `playerHp/Mp/Gold/Exp/Bag/Wallet/Loc/Flag/Num/Set/Transfer/Growth/LifeBonus/Spouse/NetAged/payGold`，NPC 侧 `npcEntry/npcAtt/npcMet/npcBag/npcGold`，世界侧 `rep/econ/weather/addEffect/removeEffect/pushLog`（:27-271）。
- **不做的事**：不夹取上界（`maxHp` 属角色系统，由调用方传 cap）、不做规则判定、不发业务事件。

### 1.3 WorldClock —— 全局唯一时间

- **时间基**：1 日 = 48 刻，1 时辰 = 4 刻，1 年 = 360 日（world/TimeBase.ts:11-20）。
- **内核**：`advance(n)` 推刻并广播事实；跨时辰发 `hour_advanced`，跨日发 `new_day`（world/WorldClock.ts:96-141）。
- **收口**：时钟**不认识任何业务系统**——日结算全部由 `plugins/daySettle.ts` 的顺序表承担（:133-136）。这是本项目从「时钟直调 10 个系统」到「时钟只发布事实」的一次结构性整改。
- **仍存的耦合**：`advance` 内直接调 `directorTick`（事件导演扫触发），因此时钟依赖 `events/EventProcessor` 而非业务系统（:110）。

### 1.4 EventBus —— 两条总线

- **bus**：引擎 → 界面的信号（`changed/toast/sheet/check/combat/screen/freeBusy…`）（events/EventBus.ts:10-24）。
- **worldBus**：系统 ↔ 系统的世界事实，带分级、通道、单 tick 配额、因果深度、死信、延后重投（:358 之后）。
- **配额与护栏**：`MAX_EVENTS_PER_TICK=64`、`MAX_CHAIN_DEPTH=6`、`MAX_CRITICAL_PER_TICK=16`、`MAX_DEFERRED=256`（:173-190）。
- **派发顺序契约**：通配订阅者（感知、世界史这类横切关注点）**先于**具体类型订阅者（:338-341）。这条曾让目击者插件静默失效，因此被测试钉住。
- **随机性**：`rng` 是唯一随机源（:33-72），`rng.pick` 对空数组直接抛错、`pickOr` 才允许兜底（:62-70）。

### 1.5 EventSchema —— 世界事件标准

- **四级**：L0 内部账目 / L1 局部 / L2 跨系统 / L3 复杂世界（events/EventSchema.ts:86-147）。未登记类型按 L1 处理（:152-154）。
- **分级是默认值不是天花板**：L2 里「死/失踪的是有名有姓的人」会升格进推演（:20-23、:304-306 未核验细节在 Executor 侧）。
- **三通道**：`critical / semantic / ambient`，默认由 level 推导，`hour_advanced` 与 `new_day` 显式声明为 critical 并配独立熔断（:64-82）。
- **事实字段**：`actor/target/location/cause/witnesses/data/parentId/sourceId/processedBy/origin`（:25-56）。`origin='reasoner'` 标记推演自造的事实，用来阻断自激（:50-55）。

### 1.6 DiceEngine —— 规则层随机

- **纯函数**：`parseDice/rollDice/resolveCheck`，四档结果（critical_success / success / failure / critical_failure）（dice/DiceEngine.ts:9-11、:75）。
- **判定次序**：自然满点必成、自然 1 必败、雨天 -1，与原型一致（《插件化世界模拟架构.md》§3.3）。
- **演出与判定分离**：`CheckResolver.check()` 只负责把结果演给玩家（1450ms 收束）并写入 `s.checks` 留痕 30 条（dice/CheckResolver.ts:37-46）。

### 1.7 Validator —— 双闸

| 闸 | 文件 | 回答的问题 | 失败后果 |
|---|---|---|---|
| 形状闸 | validation/SchemaValidator.ts:27-44 | 计划结构对不对（planId/triggerEvent/consequences ≤32/priority 0-100） | 整份拒绝 |
| 权限闸 | validation/PermissionValidator.ts | 动作注册过吗？实体存在吗？数值越界吗？重复执行吗？依据齐吗？ | 整份拒绝 |

- `validatePlan` 是唯一入口，`RuleValidator` 同时承载存档结构校验——**同一文件两件事**（validation/RuleValidator.ts:1-14）。
- 存档校验与 `hydrate` 互补：校验拒「结构错乱」，`hydrate` 补「字段缺失」，任何一侧放宽都要同步另一侧（:3-7）。

### 1.8 WorldExecutor —— 后果执行

- **内核**：只有过了 Validator 的后果才能在这里改世界；执行器**不认识任何具体系统**，处理器由登记了对应能力的系统自行注册（execution/WorldExecutor.ts:1-6、:20-36）。
- **失败语义**：验证不过 → 零执行；单条抛错 → 记录失败但不回滚已成功条目（:38-42）。
- **因果挂载**：执行期间系统发布的事件自动挂到 `plan.triggerEvent` 之下（:65）。
- **孤儿检测**：过了验证却没处理器的动作会被记为 warn——「白名单与执行器脱节」的现场必须留痕（:85-88）。

### 1.9 Plugin / Capability —— 能力登记

- **能力三分类**（`SystemSpec`）：`effects`（可被后果计划驱动，每条都有处理器）/ `pending`（世界后果、接入路径明确但今天驱动不了）/ `internal`（玩家操作与战斗裁定，刻意不驱动）（plugins/systems.ts:18-44）。
- **同源守卫**：`effects ⇔ worldExecutor.actions()` 双向钉死（:5-7、tests/arch-infra.test.ts:538）。
- **待接入分类当前为空**：`SYSTEM_SPECS` 里已经没有任何 `pending` 条目（grep 仅命中定义与透传处：systems.ts:29/46/47/256）——文档 §6.5 描述的 11 条 pending 已全部提升为 `effects`。详见 §7.1。
- **入口登记**：`internal` 能力要逐条登记真实路由名（`entries`），否则面板上的「我能做什么」无法回溯到任何可寻址入口（:34-41、:157-159）。

### 1.10 装配与调度

- **组合根**：`main.tsx` 按「运行日志 → 事件桥 → 世界模拟装配 → 存档介质 → 开发期续档」顺序装配（src/main.tsx:29-108），生产与测试走同一条 `bootstrapWorld` 路径（plugins/bootstrap.ts:8-12）。
- **装配顺序是隐式契约**：`registerCoreSystems` 必须在订阅与处理器注册之前；`attachPerception` 必须在目击者插件之前（bootstrap.ts:9-20）。
- **日结算顺序表就是契约**：17 步顺序被 `arch-day-settle.test.ts` 逐位钉住，换位会改变数值走向（plugins/daySettle.ts:96-137、:139-163）。
- **单步隔离**：任一步抛错不得带走当天其余步骤（:147-159）。

### 1.11 门面与信号桥

- **WorldAPI**：`world.query.*`（只读）/ `world.command()`（命令唯一入口）/ `world.execute()`（单条世界动词）/ `world.plan()`（整份计划）/ `world.systems.*`（插件视角）（world/WorldAPI.ts:41-260）。`execute` 与 AI 推演走**完全相同**的验证与执行路径，因此不存在绕过 Validator 的后门（:225-238）。
- **store/useGame**：Zustand 只装 UI 状态与 `rev` 信号，是世界状态的镜像而不是事实来源（src/store/useGame.ts:1-5、:103-152）。

### 1.12 持久化与观测

- **SavePort**：介质抽象（`localStorage` / SQLite / 内存），含四条可选通道——向量索引、世界史、分片、错误回调（plugins/PluginInterface.ts:207-227）。介质不支持则静默退化，只是慢，不出错。
- **分片**：`main / npcs / mind / know` 四片，被摘掉的五张表是 `npcs / memories / beliefs / knowledge / cases`（world/Shards.ts:15-27、PluginInterface.ts:195-205）。
- **RunLog**：开发期观测（`mark/info/warn/error/timer`），生产默认关闭，关掉时执行器一行额外开销都不该有（execution/WorldExecutor.ts:85-86、src/devlog/RunLog.ts）。

## 2. 领域系统

下面每一张卡片回答同一组问题：**内核 / 状态所有权 / 能力登记 / 操作面 / 纪律**。
「能力登记」一栏直接读 `plugins/systems.ts`：`effects` 能被后果计划驱动，`internal` 只能由玩家或路由驱动，空 effects 表示这个系统不接受 AI 推演。

### 2.1 角色与成长

#### character（systems/character/ 7 文件）
- **内核**：管玩家的数值来源（派生）、收益记账、成长路径、状态效果与「表」的呈现描述符；不管世界推进与战斗回合。
- **状态所有权**：`PlayerState`（types/world.ts:560）；只读 `core.CB`（战斗内状态另有一套，出战斗即清）。
- **能力登记**：`effects: gain_exp / heal_character / damage_character / add_status / remove_status`（plugins/systems.ts:50-56）。
- **操作面**：判定 `canLearn/mentorLearn/raceAllowsClass/blockersOf`；查询 `stat/mod/maxHp/maxMp/AC/atkB/xpNeed/rankName/rankTierName`（Derived）；写入 `log/gainExp/gainGold/addItem/removeItem/addRep/grantSkill/transfer/openSheet/confirmSheet`。
- **纪律**：字段改动一律经 `mutate`（Gains 的签名被 19 个系统依赖）；`Race.ts` 刻意不 import WorldState 以避免环；转职必须「技能线 + 职业 id + 转职留痕」三字段同时写，不给「只改一半」的机会（world/WorldMutate.ts:82-92）；`rankName` 是称呼、`rankTierName` 是判定，两者不可混用。
- **已核实的例外**：`Learn.grantSkill` 直接 `s.player.skills.push`（Learn.ts:51）、`battleInsight` 直改 `s.insight`——未走写入层（见 §7.2）。

#### combat（systems/combat/Combat.ts）
- **内核**：管一场战斗的回合循环、命中/伤害/状态结算与终局后果；不管叙事文本与关系判定。
- **状态所有权**：`core.CB`（`CombatState`，types/world.ts:1046；不落档）；写 `player.hp/mp/gold`、`killed`、`qf`、`net.*`。
- **能力登记**：`effects: []`；`internal: start_combat / attack / calculate_damage / apply_damage / kill_character`（systems.ts:64-72）。**战斗裁定生死，AI 只能「提出让某人受伤」，不能直接判定死亡。**
- **操作面**：`startCombat/playerAct/flee/combatUseItem/useItem/equipItem`。
- **纪律**：顺序固定「DoT → 敌回合 → 回合末递减」；回合由 `scheduler.after(520)` 驱动，UI 只按 `combatChanged` 重绘；一次 d20 不重复掷；网内比斗开局快照、终局整体还原，真身无损。

### 2.2 对话与关系

#### npc（Npcs / Chat / ContextProfile / Lod / Passersby）
- **内核**：管 NPC 的在场与作息、运行时条目、关注度分层与上下文预算、自由聊天、当日路人；不管关系传播与仇怨升级（那是 relationship）。
- **状态所有权**：`NpcDynamic`（types/world.ts:532）存在 `WorldState.npcs`；聊天历史 `chats`、日增益计数 `bondDay`。
- **能力登记**：`effects: change_goal / change_relationship`；`internal: talk / move / observe / remember`（systems.ts:57-63）。
- **纪律**：LOD 判据只能有一处；**位置是 `npcAt` 的纯函数产物**，索引只是缓存（Phase 4.2 撤掉了「每日物化位置」那一步）；`addMem` 是记忆唯一入口且统一落 `MemoryEngine`；路人不建条目、不进档；聊天产出的好感必须过 core 白名单（clamp ±2 + 日封顶）。
- **概念要点**：`Chat` 与 `Dialogue` 的双向耦合被显式做成**回调注册**（`setDeepTalkRenderer`）而不是 import，页号寄存于 `character/Sheet` 以避免成环。

#### dialogue（systems/dialogue/Dialogue.ts）
- **内核**：管对话浮层的双页呈现、逐 NPC 选项、请求判定落地、`dlgAct` 路由；不管会话历史与好感封顶（Chat），不管 AI 措辞。
- **状态所有权**：读 `chats/npcs/quests/flags/gold`；模块级持有渲染态（`dlgPage/lastDlg`），**不入档**。
- **能力登记**：`effects: []`；`internal: open_dialogue / deliver_request / give_gift`（systems.ts:181-186）。
- **纪律**：`renderDlg` 是唯一渲染入口；页号绑定对话实体、不落档；开场白不预填 + 5s 软超时回落；威胁类请求的后果必须落在规则层而不是 AI 台词里。

#### relationship（Bond / Relations）
- **内核**：管 NPC↔NPC 关系边、沿边传播、玩家侧好感/亲密度/仇怨/赠礼；不管对话文本。
- **状态所有权**：`NpcDynamic.rels`（`NpcRel`）；玩家侧 `att / intimacy / grudge / giftDay / bondProg`。
- **能力登记**：`effects: spread_rumor / form_grudge / befriend`；`internal: chat_bond`；约束「散布传闻要在人多的场合」（systems.ts:100-110）。
- **概念要点**：`bondOf(id)` 是关系的**单一事实源**——UI、聊天门禁、请求门禁、商店计价都走这一个口。
- **纪律**：遍历全表必须用不建档的 `peekRelsOf`，否则会把 L2 的 NPC 全部降成 L1；传播一跳 + 强度衰减 + visited 去环；纯 core 判定，AI 不参与；防刷三 cap（聊天日封顶、赠礼日/周封顶、连带 clamp ±2）。

### 2.3 经济与物品

#### economy（Money / Economy / Shop / Exchange）
- **内核**：`Money` 是零依赖的纯换算层（铜是唯一基数的整数，只在展示层降位）；`Economy` 管物价怎么算与商人钱袋；`Shop` 管一次买卖的完整结算；`Exchange` 管「网内星币落地成铜」这一个窗口。
- **状态所有权**：`s.econ`（品类价格指数）、`s.vendors`（各商店收购本金）、`core.curShop`（商店游标）。
- **能力登记**：`effects: add_money / remove_money / transfer_money / change_price`；`internal: buy_item / sell_item`（systems.ts:81-87）。买卖本身**刻意不让 AI 驱动**——那等于替玩家做决定。
- **纪律**：商人不是无限金币，钱袋不足即拒收；`buy` 不采信调用方给的价，一律 core 重算；卖出事务顺序是「先确认货在行囊、再扣商人钱袋」；只有 ≥1000 铜的大额交易才上世界总线；兑换所一大陆一家、星晶→星币单向。

#### inventory（Equip / Craft）
- **内核**：`Equip` 管装备实例化（七档品质 + 词缀 + 专名 + 独立计价 + 加成聚合）；`Craft` 管一次制作的完整结算（门槛 → 扣料 → 耗时 → 判定 → 产出/废品）。
- **状态所有权**：`BagSlot`（`uid` 存在即「实例」）、`s.isq`（实例序号）、`s.craft.ranks/made`。
- **能力登记**：`effects: add_item / remove_item / transfer_item`；`internal: craft_item`（systems.ts:75-79）。
- **纪律**：数值出口唯一（派生读 `instMods`、战斗读 `wornMods`）；暴击率唯一出口且封顶 40%；无 uid 的旧档槽位恒为 0 加成；专名由 uid 确定性派生、**不消耗全局 rng**；`craft()` 是唯一写入口，幂等键取推进后的目标刻；`advance(r.ticks)` 让世界照常结算，制作不会冻结世界。

### 2.4 委托与声名

#### quest（Quests / Guild）
- **内核**：`Quests` 管单条委托的状态机（给 → 进 → 复命）与奖励结算；`Guild` 管组织层——认证等级、抽成、接单门槛、层域管辖。
- **状态所有权**：`player.quests[id]{stage:'go'|'done'|'fin'}`、`player.guildRank`。
- **能力登记**：`effects: start_quest / update_quest / complete_quest / fail_quest`（systems.ts:73）。
- **纪律**：`giveQuest` 幂等；结算顺序固定（扣物 → 置 fin → 钱扣 10% → 声望/信任 → 好感 → 物品 → flag → exp）；抽成只对 `guildCut=true` 的委托抽 10%，悬赏不抽；认证等级存入独立字段而非 `flags`（flags 是布尔语义）。
- **文档-实现冲突**：`Guild.ts:8` 的头部注释仍写「认证等级存 s.player.flags」，实现与紧随其后的注释都否决了这一点（Guild.ts:79-81）。

#### reputation（systems/reputation/Title.ts）
- **内核**：管称号与声名——由既有世界状态**条件判定**授予、排序主称号、对外提供折让与称呼。
- **状态所有权**：`s.titles`（按获得顺序）、`s.titleHidden`（花钱藏起的负面称号）。
- **能力登记**：`effects: grant_title / suppress_title`（systems.ts:111-117）。
- **纪律**：称号只能由 core 依 WorldState 授予，玩家与 AI 都不能授予；隐藏只影响称呼与世界反应，历史照留；隐藏只对负面称号开放且要付费；`fameDiscount` 只作用于买价、不动卖价（否则可刷）。

### 2.5 秩序

#### law（Law / Investigation）
- **内核**：`Law` 管「算不算罪、罪多重、在哪判、判什么刑、通缉几档」；`Investigation` 管「有没有人真看见 → 才立案 → 逐日取证 → 结案」。
- **状态所有权**：`s.legal{charges,jailedUntil,executed,exiledTo}`、`player.wanted/crimes`、`s.cases`。
- **能力登记**：`effects: commit_crime / clear_crime`（systems.ts:118-122）。`clear_crime` 的口径是**抹案宗、不抹记忆**。
- **概念要点**：这是「认知分离」的下游——**证据只能来自感知表**，没人看见就没有案子（Investigation.ts:5-6、:24-26）。二手传闻按 `0.3 × fidelity` 折价，感知记录滚出缓冲后按半个证人计。
- **纪律**：`wanted` 的量纲刻意不改（1/2/3 累进、上限 3），档位只在显示层映射；追诉强度只在立案那一刻算一次；`arrest` 有案底转审判、无案底走旧罚金路径；S 级不接受赎罪；法外之地不追究、不立案。
- **口径分歧**：`wantedLv` 封顶 3（Law.ts:299），结案路径直接写 `min(5, …)` 绕过它（Investigation.ts:90）。二者与「更高值封顶神罚」的档位设计相容（Law.ts:254），但确实是同一字段的两个写入上限。

#### faction（Factions / Diplomacy）
- **内核**：`Factions` 管七轴关系怎么存怎么读；`Diplomacy` 管轴换算成什么后果（价格 / 神殿受理 / 盘查 / 准入 / 情报 / 审判从轻）。
- **状态所有权**：`s.rep`（attitude 轴，旧语义）、`s.playerRep`（其余六轴）、`s.factionRel`（势力↔势力，运行时覆盖种子）。
- **能力登记**：`effects: change_reputation / start_investigation / change_faction_relation`；`internal: gather_intel`；约束「调停势力关系要在自己的势力核心地点」（systems.ts:88-99）。
- **纪律**：七轴定义只增不改；**attitude 轴禁止走 `adjRepAxis`，直接 throw 强制改走 `gains.addRep`**；势力↔势力关系惰性写、不动世界书种子；军功/情报累积有日上限，跨日重置；`settleAxes` 幂等且「大额优先、小额不结转」。

### 2.6 世界内容与玩法

#### academy（Academy / Growth）—— 两条不同的成长路线
- **内核**：`Academy` 管学院制培养的学籍全生命周期（报名 → 修业考核 → 毕业 → 学位称号）+ 学费/资助/服役账务（§101）；`Growth` 管另外三条线（师徒 / 神殿培养 / 自学）。
- **状态所有权**：`AcademyState`（types/world.ts:699）、`player.growth`（`GrowthState`，:777）。
- **能力登记**：`effects: []`；`internal: academy_enroll / academy_study`（systems.ts:139-144）。修业触发点在 UI，不经后果计划。
- **纪律（两个文件相反的做法，值得注意）**：`Academy.ts:8` 自述「一切状态改写只在本文件内完成」；`Growth.ts` 则统一走 `mutate.playerGrowth()`（Growth.ts:70/157/168）。同一域内两种写入纪律并存。
- **日结算**：`serviceTick` 是顺序表第 17 格（daySettle.ts:136）。

#### dungeon（Dungeon / Abyss / Monsters）
- **内核**：`Dungeon` 管 100 层爬层的「下潜 → 推进 → 遭遇 → 后果」闭环与层志；`Abyss` 管星渊魔气 `leak 0-5` 的累积、探查与封印拉锯；`Monsters` 是纯查询表（来源 / 等级 / 食物链）。
- **状态所有权**：`s.dungeon`、`s.abyss`；魔物数值本体在世界书，不在状态里。
- **能力登记**：`effects: []`；`internal: enter_dungeon / descend`（systems.ts:146-152）。
- **纪律**：层数据全在数据层、零逻辑；**陷阱最多打到 1 血、不致死**——「地下城的死亡只来自战斗，这是规则而非妥协」（Dungeon.ts:268-281）；`inRun` 但人不在入口视为中断，自愈（:104-113）；撤退不写 `cleared`；首通按 `cleared` 幂等。
- **L3 的唯一生产源**：`leak` 跨过 `crisisAtLeak` 时发布 `abyss_breach`，是当前唯一在跑的 L3 链路（Abyss.ts:59-68、EventSchema.ts:132-138）。

#### starnet（StarNet / Towers）
- **内核**：`StarNet` 管星枢网**网内层**——入/出网门禁、七塔授权、网内经济闭环（寄售 / 星市 / 比斗 / 兑换 / 参悟 / 试炼 / 竞技 / 星殿）；`Towers` 只管七塔的地理归属与「够不够得着」。
- **状态所有权**：`s.net`（`NetState`）；**网内只动 net 域，真身 hp/gold 无损**。
- **能力登记**：`effects: []`；`internal: star_trade / star_duel / chat_free / net_access / star_market / star_tower / star_arena / star_council`，每条都登记了真实路由名（systems.ts:153-171）。
- **纪律**：入网禁入、出网禁、财物只进不出，「判定全在 core，AI 只叙事」；`net_entered / net_exited` 是事实补全，**当前没有生产侧订阅者**（StarNet.ts:41-45）；`Towers.ts` 独立成文件的唯一理由是解 `StarNet ↔ Abyss` 的循环依赖。

#### religion（Deity / Theoselect）
- **内核**：`Deity` 管六大神系的 `favor` 累积 → 信仰阶位自动晋阶 → 神迹消耗与冷却 → 候补神晋升收口；`Theoselect` 管百年神选的阶段推进与确定性名次奖励。
- **状态所有权**：`s.favor`、`s.favorDay`（祈祷日限）、`s.theoselect`（`TheoselectState`）。
- **能力登记**：`effects: []`；`internal: pray / divine_intervene`（Deity）、H5 五阶段全部 internal（systems.ts:132-138）。
- **纪律**：神名/阶位/阈值一律读 `deities.json`，不硬编码任何神名；`Theoselect` **不 import Deity**，H5↔H6 的耦合由组合根注入 `setAscendHook` 完成，没有钩子时只置 flag、不臆造神职数据（WorldRuntime.ts:50-52、Theoselect.ts:300-311）；名单同分按 id 稳定排序。

#### travel（systems/travel/Travel.ts）
- **内核**：一个文件承载四组概念——跨大陆路线、大陆可达性、城内可达性与最短路、地标与六星险区，再加交通体系（速度等级 / 城内交通 / 传送阵三重门）。
- **状态所有权**：读 `player.loc/gold/level/flags`；写 `playerLoc` 与「到过/解锁」类 flag。
- **能力登记**：`effects: []`；`internal: travel_to`（真实路由 `travel` / `go`）（systems.ts:124-131）。
- **纪律**：**刻意不做自动多跳**——每一跳都要结算夜间遇袭与城卫盘查，一次走完会把这些吃掉（world/index.ts:77-79）；季节封锁是纯函数，地图 / 提示 / `canDepart` 三处共用同一判据；出发流程的 rng 顺序固定（天气延误 → 遭遇选取 → 遭遇判定）。

#### codex（systems/codex/Codex.ts）
- **内核**：文献图鉴的收集与解锁（观察 / 残卷 / 深谈三途）+ 只读视图。
- **状态所有权**：`s.codex{unlocked, found, obsDay}`。
- **能力登记**：`effects: []`；`internal: unlock_lore`（systems.ts:172-178）。
- **纪律**：`tryUnlock` 是唯一写入口且幂等；关键词反查由 core 自持——**不依赖 ai 层**（分层方向 core ← ai 不可逆）；观察每地点每日上限 2；读残卷确定性解锁「序号最小未读」，不掷随机。

#### naming（systems/naming/Naming.ts）
- **内核**：纯生成层——人物名 + 六维（地区 / 组织 / 装备 / 魔物 / 层名 / 技能遗迹）的公式化生成、稀有度掷档、避雷与撞名拦截、lore canon 取名。
- **状态所有权**：**不读写任何 WorldState**，只读三份数据表；这是全项目最纯的模块。
- **能力登记**：`effects: []`；`internal: generate_name / validate_name`，且明示「没有玩家侧命令入口」（systems.ts:187-193）。
- **纪律**：随机一律走统一 `rng`（可 seed、可注入）；未知种族回落人类公式而**绝不抛错**；生成结果永不命中 blocklist；槽位填不满的模板不得吐给玩家。

#### rites（systems/rites/Rites.ts）
- **内核**：把「婚配 → 配偶 → 寿终 → 按所在地丧俗安葬 → 按所在地继承制度分遗产」接成闭环。
- **状态所有权**：`player.spouse`、`flags.life_exhausted / rites_done`。
- **能力登记**：`effects: []`（成婚是 UI 动作、身后事由日结算驱动）；全部走 internal 查询（systems.ts:218-226）。
- **纪律**：婚俗丧俗按**所在地**大陆算，不按出身；世界书没给 NPC 岁数，就只校验「在不在本地」，不编造年龄拦人；身后事必须紧跟寿数检查（它读的就是上一步置下的事实）；**不在 Lifespan 里调 rites**，否则形成 `timeslip ↔ rites` 环。

#### timeslip（Timeslip / Lifespan）
- **内核**：`Timeslip` 管小世界时间流速（加速 1:5 / 减速 5:1 / 变异 / 静止型）+ 境界寿命表 + 流放刑期换算；`Lifespan` 管年龄随外界时间自然增长、境界抬升延长寿数、网中历时不耗寿。
- **状态所有权**：`player.birthTick / netAgedTicks / lifeBonus`；寿终只置「事实」不发后果。
- **能力登记**：`effects: enter_timeslip`（入小世界练功是玩家动作）；寿命与换算为 internal 查询（systems.ts:210-217）。
- **纪律**：**存出生刻、不存年龄**——年龄是派生量，存下来迟早漏同步（Lifespan.ts:9）；外界时间必须**真的走**（推进 `advance(outerDays × 48)`），闭关百年要在世界留下痕迹；境界名只有一处映射（Derived），本模块不再自己写第二份。

#### commnet（systems/commnet/CommNet.ts）
- **内核**：八种通讯方式的距 / 费 / 时效三维判定，跨大陆即时与否决定任务时效。
- **能力登记**：`effects: send_message`（要扣钱、要发事件，故进 effects）；其余为查询（systems.ts:202-208）。
- **纪律**：**事件是本模块的对外出口**——通讯系统自己不去通知任何人，任务与势力各自订阅决定怎么反应（CommNet.ts:56-59）；距离只用两个常数（同大陆 60km / 跨大陆 1500km），不新引入数据源；面板明确「发讯只传话，不传物」。

#### culture（systems/culture/Culture.ts）
- **内核**：禁忌触犯是判定（扣声望 + 发事件）；饮食 / 服饰 / 婚丧 / 娱乐只供叙事与面板直读。
- **能力登记**：`effects: violate_taboo`（systems.ts:228-234）。
- **纪律**：不在该大陆即拒绝；`taboo_violated` 发出去之后，各势力与关系系统自行决定怎么反应。

#### adventuring（systems/adventuring/Adventuring.ts）
- **内核**：宏观面——各阶冒险者的投入产出与死亡率、阶层财富分布、各大陆产业与特产、地下城兑换物。与 `economy`（玩家买卖）分区。
- **能力登记**：`effects: []`（领兑换物的触发点在 UI 公会柜台，不是 AI 能决定的动作）；全 internal（systems.ts:236-243）。
- **纪律**：用**阶序**对齐两套命名空间（认证 D/C/B/A/S ↔ roi 表行），修掉了「手抄一份 map 与权威表各写一份」；「core 必须自己拒重复，UI 把按钮置灰只是体验层」。

### 2.7 认知与编排层

#### actions（ActionParser / ActionExecutor）
- **内核**：`ActionParser` 是自由行动的**意图闸门**（LLM 通道优先、正则降级）；`ActionExecutor` 把已确定的意图落成世界改动。前者不改世界，后者不含解析。
- **状态所有权**：两者都不持有状态；写入一律经 `need()` / `mutate` / `sync`。
- **纪律**：双通道必须产出**同构**的 `IntentParse`，全部汇入 `executeIntent` 这一个汇合点；复合句拆解 ≤3 步且要过二次白名单；检定步留 1600ms 演出窗，遇到战斗爆发直接截断；`attack` 只认显式指名；core 侧有 in-flight 锁做去重。
- **概念位置**：这是「玩家自由文本」与「枚举命令」之间唯一的翻译层，也是「UI 文案 = 能力承诺」这条产品约束的落点——界面提示里给的例句必须真能执行。

#### events 外围（Perception / Sampling / EventStore / EventProcessor）
总线与事件结构见 §1.4-1.5，这里补四个只做单一件事的模块：

- **Perception**：事件级感知。按「在场 NPC × 事件显眼度」判定目击者并登记到感知表；`witnessesOf` 只判定不登记，`perceiveContext(npcId)` 才是喂 AI 的正确入口。
- **Sampling**：确定性采样 `sampleHit(seed, eventId, npcId, purpose, probability)`——**不消耗主随机流**，与遍历顺序、NPC 数量都无关。概率不是有限数时直接抛错，不静默降级。
- **EventStore**：事件簿与世界史（环形 500 条，不入主档，走 `savePort` 的独立通道）+ `timeline()` / `addHistory()` 的因果沉淀。
- **EventProcessor**：World Director。按 `events.json` 的触发谓词（`evalTrigger`）与后果表（`applyEffect`）扫触发，`directorTick` 由时钟的跨时辰广播驱动。

这四者合起来构成「世界自己会动」的那部分机制：**不需要玩家操作，世界也会产生事实**。

#### memory（18 文件，按职责分十块）
- **数值表**（MemoryTypes.ts）：置信度 / 重要性 / 衰减率 / 强度的查表——「一条记忆有多硬」只有这一个来源。
- **存储与容量**（MemoryStore.ts）：读写原语 + **容量淘汰的唯一执行点**（每角色 80 条，按当前强度淘汰）。
- **引擎门面**（MemoryEngine.ts）：回答「知道什么 / 多清楚 / 从哪知道 / 如何遗忘」，把感知沉淀为角色记忆；`addMem` 是系统侧唯一入口，写入即留痕。
- **验证闸**（MemoryValidator.ts）：`MemoryProposal → ProposalVerdict`。AI 通道提供的记忆必须过闸。
- **生命周期**（lifecycle/MemoryLifecycle.ts）：衰减、强化、压缩（压缩另立摘要条、原条目降 `archived` 而不抹正文）、以及 LOD 分频（`memoryDue` / `memoryTick`）。
- **信念**（belief/BeliefSystem.ts）：同命题聚合成 Belief；**明确不做推断链与心理模型**。
- **传播**（propagation/InformationPropagation.ts）：传播即重算，只写记忆、**永不回写世界事实**；`gossipTick` 挂在日结算第 6 格。
- **检索**（retrieval/*）：结构化过滤（`visibleTo`）+ 关键词 + 混合打分 + 摘要与 token 预算；语义分量只在缓存命中时计入并重新归一化。
- **向量**（vector/*）：事实与向量**分开存**；内存向量库做全量余弦 + LRU（上限 2000）；`cosine` 在维度不等时直接判 0，不给「看起来合理」的假分数。
- **嵌入**（embedding/*）：provider 槽位 + 缓存（字节预算 900k）+ 持久化；换模型或维度不符的旧向量直接作废（两套向量空间的余弦没有意义）。
- **老表迁移**（LegacyMemory.ts）：把 `NpcDynamic.mem` 单向迁进新记忆表——认知层曾有两个真相来源，这里做一次性收口。

### 2.8 AI 层


AI 层的整体定位只有一句话：**它产出的只有文本与判断，永远不落状态。**

- **gateway.ts**：管「当前 `AiPort` 是谁」（OpenAI 兼容 or rule-sim）与热切换；不管判定与状态。
- **llmConfig.ts**：配置读写（`localStorage tq2_ai_cfg_v1`）与可用性判定；timeout 夹取到 [1000, 60000]，读写两侧同收口；`tiers`（light/heavy）已预留但未接线。
- **openaiCompat.ts**：适配器。异步通道只产文本与判断，失败一律返回 `null`；同步三通道直接委托 `ruleSim`。
- **ruleSim.ts**：无模型兜底（叙事取句 / NPC 决策 / 八层上下文），只读世界书与 WorldState。「不配模型也能完整通关」这条产品承诺由它兜住。
- **WorldReasoner.ts**：推演编排（门槛 → 上下文 → 端口 → 校验 → 执行 → 事件）。`origin='reasoner'` 的事件一跳即止，防止模型用 `create_event` 把推演递归放大；并发上限 3、每 tick AI 预算 10。
- **ContextBuilder.ts**：最小必要上下文（明令禁 `SELECT *`）；**只下发可执行能力**，把做不到的动作写进提示词等于主动引导模型产出必被拒的计划。
- **ConsequencePlanner.ts**：模型原文 → 严格计划；解析失败即拒绝，不猜。
- **ruleReasoner.ts**：规则推演兜底——命案有目击者 → 势力立案，亲族 → 追凶目标。**找不到依据就不推演**，每条后果都绑 `triggerEvent/reason/source`。
- **persona.ts / retriever.ts / helpers.ts / embeddingCompat.ts**：人设锚文本（所有 NPC 类通道共用，禁止各适配器自己拼 prompt）、lore 检索纯函数、core 只读查询桥、向量适配器与失败冷却（换模型即清缓存）。

### 2.9 持久化与表达层

- **repo/index.ts（localStorage）**：整档 + 四分片 + 向量键 + 世界史键；**四片齐全才算完整档**，指纹不符即整份作废并回落上一份完整档；写失败留脏标记待重试。
- **repo/sqlite.ts（Tauri）**：内存镜像 + 串行写穿队列，用来满足 `SavePort` 的同步契约；`saves(id,ver,updated_at,payload)`。
- **store/useGame.ts**：Zustand 只装 UI 状态与 `rev` 信号；`attachCoreBridge` 是引擎到界面的唯一桥；切屏复位浮层与计时器。
- **ui/**：只渲染 + 发命令。61 处写操作全部经 `cmd()`；非命令的写口只有三处例外——错误兜底页的 `resetWorld`、系统面板保存 AI 配置、Blob 导出存档。`SheetHost` 承载全部由 core 描述符驱动的浮层（对话 / 商店 / 抉择 / 战斗道具 / 聊天 / 制作 / 图鉴）。
- **main.tsx**：唯一装配点，顺序为「观测 → 事件桥 → 世界模拟架构 → 存档介质（Tauri 失败回落 + toast）→ 向量索引恢复 → DEV 续档 → 关闭前 flush → HMR dispose → 渲染」。

## 3. 认知链：这个项目最独特的一条抽象

事实如何在角色之间「变形」，是全项目最值得单独抽象的一条链。它把「世界真相」与「某人以为的真相」彻底分开：

```
世界事实 WorldEvent（客观，带 actor/target/location/cause/witnesses）
   │  Perception：显眼度 × 在场 × 确定性采样（events/Perception.ts:80-104）
   ↓
感知表 PerceivedFact{via:'witness'|'rumor', fidelity}（WorldState.knowledge，每 NPC ≤40 条）
   │  MemoryEngine：把感知沉淀为角色记忆（memory/MemoryEngine.ts:164-274）
   ↓
记忆 Memory{confidence, importance, visibility, emotion, sourceEventId}（每角色 ≤80 条，按强度淘汰）
   │  衰减 / 强化 / 压缩（memory/lifecycle/MemoryLifecycle.ts）
   ↓
信念 Belief{proposition, subject, predicate, object, confidence}（由记忆聚合，非独立事实）
   │  beliefActions 规则表（data/world/memory.json:70-89）
   ↓
行动 → 走进 WorldExecutor → 又变成新的事实（回到链首）
```

只属于这条链的几条概念约束：

- **亲历优先**：已听说的事遇到亲历时升级为亲历，不会被传闻覆盖（Perception.ts:106）。
- **好感变化不产生目击者**：显眼度为 0——那是两个人的私事，旁人不该「目击」到别人心里的秤（《插件化世界模拟架构.md》§3.8）。
- **传闻按手数衰减**，`fidelity < 0.15` 自行中断；`secret / restricted` 级记忆不外传，`private` 可以转述（memory/propagation/InformationPropagation.ts:20-36）。
- **召回只强化、绝不改置信度**——被想起来不等于被证实（MemoryLifecycle.ts:40-45）。
- **冲突记忆都留着**，由置信度而不是删除来定胜负（memory/belief/BeliefSystem.ts:5）。
- **推测不得高置信**（inference < 0.5）、亲历必须带 `sourceEventId`、`secret` 不得变 `public`（memory/MemoryValidator.ts:58-70）。
- **喂给 AI 的是「他记得的」，不是世界史**：推演取 `perceiveContext(npcId)`，谣言、误会与信息不对称因此是系统自然产物，不是特例。

### 7.2 重复所有者（两处都在写，语义重叠）

1. **`StatusEffect.left` 有两个衰减执行者**：刻级每刻 -1（WorldClock.ts:77-94，由 `advance` 每刻调用 :101），日边界再扣 48（daySettle.ts:82-94，顺序表第 13 格 :116）。
   **实测**（临时用例，跑完已删）：给玩家挂一个 `left=96`（名义两天）的效果，推进 48 刻——
   - 不注册日结算 → `left` 剩 48
   - 注册日结算 → 条目已被移除（`undefined`）
   即一天实际扣掉约 96 刻，是设计值的两倍。**这是一个可观测的数值偏差，不是注释问题。**
2. **通缉等级有两个写入上限**：通用入口封顶 3（Law.ts:299），结案路径封顶 5（Investigation.ts:90）。后者与「六档、更高值封顶神罚」的档位设计相容（Law.ts:254），但同一字段有两条口径，读代码的人必须先知道「从哪进来的」才能算准上限。
3. **写入层的覆盖不均**：`WorldMutate` 自称「世界状态的唯一写入实现点」，实际只有 player 字段族有原语；`s.net.starcoin`、`s.dungeon`、`s.abyss`、`s.favor`、`s.theoselect`、`s.codex`、`s.craft`、`s.econ`、`s.vendors`、`s.cases`、`playerRep`、`factionRel`、`isq` 都是就地直改（例如 CommNet.ts:73、Theoselect.ts:341、Codex.ts:93-94、Dungeon.ts:93-97），`Learn.grantSkill`（Learn.ts:51）与 `battleInsight` 也不经原语。
   这不是 bug，但意味着「唯一写入点」这条抽象在状态树的子域上**不成立**——它其实只是「player 核心字段的唯一写入点」。
4. **同域两种写入纪律**：`Academy.ts:8` 声明「一切状态改写只在本文件内完成」，同域的 `Growth.ts` 则统一走 `mutate.playerGrowth()`。

### 7.3 未通电的接线位（结构在位，没有生产者在跑）

1. **事件总线多数出口只有「记录」语义**：订阅侧目前只有 5 条（`quest×character_died`、`law×crime_committed`、`codex×lore_unlocked`、`relationship×grudge_formed/rumor_spread`、`economy×large_trade`，plugins/subscriptions.ts:47-106）。`message_sent / last_rites / married / taboo_violated / life_exhausted / travel_arrived / net_entered / net_exited` 在生产代码里没有订阅方，只出现在事件分级表、感知权重表与测试里。
2. **L3 事件只有一个生产源**：`abyss_breach`（Abyss.ts:59-68）；`city_at_war / ruler_died / npc_missing` 等在分级表里但无生产者（EventSchema.ts:132-138）。
3. **玩家杀死 NPC 缺玩法入口**：战斗系统只接受魔物 id，所以「命案升格进推演」这条链在玩法上不可达（《插件化世界模拟架构.md》§6 自陈）。
4. **`pending` 分类空置**：三分类的语义很好（可见、不可驱动），但当前代码里没有任何一个实例——「接了一半」这个中间态在运行中的项目里已经不存在了。

### 7.4 值得追问的概念缺口

- **`systems` 目录与能力登记不是同一个切分**：一个目录可以登记多条能力（combat），一个文件可以承载四组概念（travel）。若将来要让「系统」这个概念可被机器校验，需要先决定以哪一侧为准。
- **`world/index.ts` 是事实上的第二门面**：它重导出上百个系统函数（world/index.ts:9-180），而 `WorldAPI` 才是设计上的统一门面。表现层「只从 index 进引擎」这条规矩因此允许绕过 `world.query` 直接读系统函数。
- **`ai/ContextBuilder` 反向 import 了 `world/WorldAPI`**（ContextBuilder.ts:8）：WorldAPI 自己承认这是「唯一一处系统侧反向 import 门面」（WorldAPI.ts:9-10）。分层方向没被破坏，但「门面只向下依赖」这句话需要一个例外注脚。
