# 运行日志（开发阶段观测）

## 一句话

应用启动后自动记录「世界实际发生了什么」——事件、推演、校验、执行、存档、报错——
实时可看、可过滤、可导出；**只读观察，不参与任何判定**。

它和玩家可见的 `s.log` 完全是两回事：那是叙事，这是观测数据。

---

## 怎么开

| 场景 | 开关 |
| --- | --- |
| 开发构建（`npm run dev`） | **默认开启**，无需配置 |
| 打包版本想观测 | 控制台执行 `localStorage.setItem('tq2_devlog','1')` 后重启（`'0'` 关） |
| 一次性打开面板 | 地址栏加 `?runlog=1`，或按 **Ctrl+Shift+L** |

面板默认收起，右下角有一个 ⌘ 按钮。未启用日志时面板完全不渲染（零成本）。

---

## 面板能做什么

- **实时流**：贴着底部看，自动跟随；手动上滚自动退出跟随，点「跟随」按钮回到贴底
- **暂停**：冻结视图（缓冲照收），用来仔细看某一刻的状态
- **通道过滤**：九个通道任选（含各自计数），「全部」一键复位
- **级别门槛**：debug / info / warn / error 以上
- **搜索**：消息与结构化载荷一起搜
- **导出 / 复制**：当前缓冲导出成 JSON（含统计与全部条目），带时间戳文件名

---

## 通道

| 通道 | 记什么 |
| --- | --- |
| 装配 | 启动阶段标记：日志接入、组合根装配、存档介质、死信观察者 |
| 世界事件 | 每条世界事实（自动，来自 `worldBus` 通配订阅）：类型、级别、actor/target/location、因果父、`origin` 标记、目击者数、载荷摘要 |
| 战斗 | 开战 / 每次伤害 / 脱离 / 胜负。`damage_applied` 按 §12 是 L0「不进总线」，但不进总线不等于不该被观测——面板上除了界面开关什么都看不到，一场 60 回合的战斗事后无从复盘 |
| 推演 | 推演入口与上下文规模、模型输出是否成为合法计划、落地结果（executed/rejected/newEvents） |
| 记忆 | 写入 / 召回强化 / 提案落库与被拒 / 日边界生命周期。认知层此前是观测盲区：记忆表在涨，但「谁因为什么记得了什么」查不回来 |
| 校验 | 计划被拒的原因（形状不合法 / 第几条后果 / 具体判据） |
| 执行 | 计划执行完成（条数、新事件数）、**「动作没有执行器」告警** |
| 存档 | 存档写入失败（与玩家侧 toast 同源） |
| 耗时 | 关键路径计时（推演、执行），超过 1s 自动升为 warn |
| 错误 | 未捕获异常、未处理的 Promise 拒绝 |
| 界面 | 场景切换、toast、检定卡、战斗界面开关（`changed` 之类高频信号不记） |

级别约定：`L3 事件 → warn`、`L2 → info`、`L0/L1 → debug`，这样"复杂世界事件"在流里一眼可见。

## 自动来源与插桩点

自动（不需要改业务代码）：

- `worldBus` 通配订阅 —— 世界事件主干（订阅 owner 是 `runlog`，不参与幂等记账）
- `bus` 订阅 —— 界面侧关键信号
- `window.onerror` / `unhandledrejection` —— 全局错误
- 死信观察者（`plugins/bootstrap.ts` 的 hook）—— 被截流的世界事件

手动插桩（六点，都在关键路径上）：

| 位置 | 记什么 |
| --- | --- |
| `ai/WorldReasoner.reasonAbout` | 上下文规模、模型输出结论、落地结果、耗时 |
| `execution/WorldExecutor.execute` | 执行完成、无处理器告警、耗时 |
| `validation/RuleValidator.validatePlan` | 拒绝原因（整份计划作废的现场） |
| `main.tsx` 的 `repo.onError` | 存档写入失败 |
| `systems/combat/Combat.ts` | 开战 / 每次伤害（含暴击与剩余血量）/ 脱离 / 胜负 |
| `memory/MemoryEngine.ts` | 记忆写入（owner·类型·来源·重要度·置信度）、召回强化、提案落库与被拒、日边界遗忘/压缩/传话 |

## 控制台用法

DEV 构建把 `runLog` 挂在 `window.__tq` 上：

```js
__tq.runLog.stats()          // { total, kept, dropped, uptimeMs, byChan, byLvl, cap }
__tq.runLog.entries()        // 全部条目（副本）
__tq.runLog.tail(50)         // 尾部 50 条
__tq.runLog.exportJson()     // 导出文本，可直接喂给分析脚本
__tq.runLog.enable(false)    // 当场关掉
```

## 装配顺序（一条需要知道的细节）

`attachRunLog()` 在 `main.tsx` 里**先于** `bootstrapWorld()` 执行，所以它是世界事件总线上的
**第一个通配订阅者**。这样做是为了把「启动装配」本身也记下来（否则开局那几条日志会漏）。
代价是它跑在感知 / 世界史 / 记忆 / 推演之前——因此它**只读事件对象本身**，
不查任何派生表（查了也会读到还没写入的旧值）。

它出任何问题都不许冒泡：`push` 整段有兜底，宁可少一条日志，也不能让感知或记忆被跳过。

---

## 设计边界（刻意不做的事）

- **不入档**：日志是运行态数据，不进 `WorldState`、不进存档、不进世界事件总线。刷新即重置。
- **不落盘**：只有内存环形缓冲（1000 条），导出靠面板按钮。要做持久化就照 `SavePort` 的可选通道加，别把日志塞进世界状态。
- **零依赖**：`src/devlog/` 不 import 引擎/UI/存储（由 `eslint.config.js` 的 `arch-devlog` 规则强制），世界日与刻由装配方注入 —— 否则会把观测通道焊进被观测的对象。
- **关闭即零成本**：`runLog.enabled` 为 false 时所有写入与计时器直接返回；面板不订阅、不渲染。
  调用点也守了这条：推演的上下文统计、执行器的「无处理器」扫描都用 `runLog.enabled` 包住，
  不会出现「关了日志还在算参数」的情况。
- **面板的过滤逻辑是可测的**：通道/级别/关键字筛选抽在 `devlog/RunLogFilter.ts`（纯函数，有单测）。
  面板本身的渲染没有自动化测试——仓库的测试环境是 node（无 DOM，也不引入 jsdom），
  这一点用真机截图 + 手动核对覆盖，不假装有。
- **观察者不能影响世界**：订阅者抛错会被吞掉（日志是最外层），死信/限流等引擎机制不因日志而改变。

## 测试

`src/tests/devlog.test.ts`（21 例）：环形封顶与丢弃计数、关闭后不记、通道/级别计数与 clear 语义、
订阅与退订与清空通知、`since` 游标跨 clear、导出可解析、计时器（含「创建后再关闭」的边界）、
载荷收敛（长串截断 / 容器形状可分辨）、面板过滤器（通道 × 级别 × 关键字 的与运算）、
自动装配（世界事件入日志、L3 记 warn、界面信号只记关键几类、卸载后订阅者数量还原、快照注入）、
插桩（校验拒绝留下原因、脱节时 exec 告警、拒绝与执行结果分流到两个通道），
以及一条「坏掉的快照注入不影响世界判定」——它是「观察者不影响世界」的直接证据。
